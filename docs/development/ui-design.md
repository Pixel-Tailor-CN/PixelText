# 界面设计规范

## 信息与交互

- 用布局、控件和状态表达操作，不在日常页面堆叠“点击这里”“可以通过……”等教学文字。
- 文案应提供用户当前需要的信息：状态、错误、输入约束或真实风险。重复标题、按钮含义和已显示的状态不再解释。
- 页面突出当前主要任务，低频管理操作放在更多菜单或独立设置入口；避免同一动作出现多个竞争入口。
- 只有用户主动发起修改、删除、上传等操作后，才出现相应选择和确认。保留不可逆操作、短信发送和样本上传所需的明确确认。
- 输入约束跟随输入位置，错误跟随出错控件；不要把下一个步骤的选择提前堆到当前页面。
- 优先用留白、对齐和字号区分层级，不为每个表单区块或列表条目添加分隔线。
- 不常驻重复标题、开关或按钮含义的辅助小字。初始空表单不显示错误；输入不合法时就近提示，上传说明集中在提交确认步骤。

## 空状态

- 无数据页面使用已有风格的插画与一句简短、具体的文案。复用 `AppEmptyState`，不要只有“空数据”或单个占位图标。
- 页面已有新增入口时，空状态不再复制一个同义按钮。
- 区分真正无数据、没有搜索结果、加载、无权限和请求失败；失败不可伪装成空状态。
- 插画不承担交互和必要信息，使用空的无障碍描述；正文保留可读语义。
- 全页空态在可用空间中居中；嵌入列表或面板时让布局约束决定尺寸，兼顾小屏、横屏与大字体。

## Material 3 Expressive 色彩

- 沿用 `MaterialExpressiveTheme` 和 `MaterialTheme.colorScheme`，支持动态取色和深色模式。
- 主操作和选中状态使用主题强调色；普通内容通过 `surfaceContainer*` 层级区分，不依赖大面积强调色或随意透明度叠加。
- 容器与内容颜色成对使用：`primaryContainer/onPrimaryContainer`、`secondaryContainer/onSecondaryContainer`、`errorContainer/onErrorContainer`；中性表面使用 `onSurface` 和 `onSurfaceVariant`。
- 错误色用于错误和危险操作，非错误状态不要滥用红色；状态还应有文字或图标，不能仅靠颜色区分。
- 保留用户自选颜色、品牌标识、插画与媒体本身的颜色；不机械地把所有颜色替换成主色。
- 联系人默认头像使用原有固定配色，不跟随 Material 3 或动态取色；会话列表和搜索结果保持一致。
- 优先组件默认的禁用、选中、焦点与按压样式；避免自行拼接低对比颜色。

依据：[Material 色彩角色](https://m3.material.io/styles/color/the-color-system)、[Compose Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3)。

## 验收

检查空态与有数据状态、主要操作与返回、错误与重试、浅色与深色、动态取色和大字体。区分源码检查、模拟器实际验证与真机未验项，不以编译通过替代完整交互验证。
