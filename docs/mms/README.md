# MMS 接收维护说明

PixelText 以系统 Telephony Provider 为消息来源，通过本地镜像和私有附件库提供彩信展示。接收协议确认属于接收链路；用户主动编辑和发送 MMS 不属于本阶段范围。

## 内容处理

- `MmsContentModel` 保存全部部件、正文选择、附件标识及 SMIL 页面。嵌套 multipart/alternative 只影响正文展示，不丢弃其他原件。
- `MmsPartReader` 对文本及流进行有界读取。历史 Provider 内联文本可生成 UTF-8 副本，界面明确区分副本与原始附件。
- Coil 加载本地图片；Media3 提供共享播放控制与生命周期管理。媒体解码能力取决于设备，失败时仍可保存或外部打开原件。
- HTML 经 jsoup 清洗后由系统 WebView 离线展示，不使用 Custom Tabs，也不打包浏览器内核。禁用脚本及网络回退，只允许访问当前消息中的资源；外部链接由用户确认后打开。
- vCard 与日历分别显示结构化卡片，通过系统界面确认导入。不支持的字段或格式保留原件并提示限制。
- FileProvider 分享单个受控 URI，文件保存使用系统文档界面。文件名按 UTF-8 字节预算截断并保留扩展名。

## 接收与恢复

`MmsReceiver` 持久化有界原始事件并调度后台任务。接收协调器处理通知去重、源 SIM、下载、解析、Provider 写入及镜像同步。解析或保存失败保留下载 PDU，允许本地重试。

内容提交后才发送协议确认，确认失败独立退避重试，不重新下载正文。确认事务保持原始标识与字节，不承诺网络层恰好投递一次。送达和已读报告关联已有发件记录，不匹配时保留为独立协议事件。

Room 使用显式迁移；内容 revision、索引版本和消息删除事件共同维护派生内容的有效性。Provider 未发出外部附件删除通知时，还需依赖后续生命周期协调恢复。

## 维护边界

Android 12 下限、真实运营商、双实体 SIM 和物理音频输出需要设备验证。日历、联系人、邮件等外部操作还依赖系统是否存在可用处理程序。模拟器成功不能替代这些验证。
