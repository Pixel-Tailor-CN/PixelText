# 验证码短信自动删除设计

## 目标

在设置页面提供默认关闭的“自动删除验证码”功能。开启后，用户可以配置验证码短信的保留天数，应用通过 WorkManager 每隔 5 小时清理超过保留期限的验证码 SMS。

## 配置

- `autoDeleteVerificationCodesEnabled`：是否启用自动删除，默认 `false`。
- `verificationCodeRetentionDays`：验证码短信保留天数，默认 `7`，有效范围为 `1–365`。
- 设置页面始终显示开关；仅在开关开启时显示“验证码保留时间”配置项，摘要展示当前天数。
- 点击配置项后通过输入对话框修改天数。输入框只接受十进制数字；空值、`0`、负数、非数字和超出范围的值均不得写入配置，并应显示明确错误。

## 调度

- 使用 WorkManager 唯一周期任务，执行间隔为 5 小时。
- 开启功能时注册或更新周期任务，关闭时取消任务。
- 应用启动时根据当前配置再次同步任务状态，处理应用升级、进程终止或历史任务残留。
- Worker 执行时重新读取开关与保留天数。即使已被系统调度，功能关闭后也不得执行删除。

## 清理流程

1. 使用当前时间减去保留天数得到截止时间。
2. 从验证码索引查询时间早于截止时间的 SMS 索引项，不处理 MMS。
3. 删除对应的系统 SMS 本体。
4. 系统 SMS 删除成功后删除对应验证码索引；如果短信本体已经不存在，同样删除陈旧索引。
5. 如果应用不是默认短信应用、缺少权限或系统短信删除失败，不删除对应索引，等待后续任务重试。
6. 清理完成后触发短信数据和验证码视图所需的数据刷新通知。

时间边界采用严格早于截止时间：例如保留 7 天时，恰好位于截止时间的短信不在本轮删除范围内。

## 代码边界

- 设置模型与持久化仍由 `AppSettingsRepository` 负责。
- 设置页面只处理输入状态、校验提示和调用 ViewModel。
- 验证码仓库负责查询过期索引及协调索引清理，不把 ContentProvider 操作放进 UI。
- 独立 Worker 负责读取配置并触发清理。
- 独立 Scheduler 负责唯一周期任务的注册、更新和取消。

## 异常与日志

- Worker 对无效的历史配置使用默认值 7 天，并将值约束到 `1–365`。
- 单条短信删除失败不得导致已成功删除的其他短信回滚。
- 日志使用英文、短语格式和键值对，不记录短信正文、验证码或其他敏感内容。
- 可恢复异常返回 `Result.retry()`；功能关闭或没有过期数据返回 `Result.success()`。

## 验证

- 编译 Debug Kotlin。
- 运行 Android Lint。
- 在模拟器检查开关默认关闭、条件显示、数字键盘、非法值校验和配置持久化。
- 使用缩短截止时间或预置旧验证码数据的方式手动触发 Worker，确认系统 SMS 与验证码索引同步删除。
- 确认关闭开关后唯一周期任务被取消，重新启动应用后任务状态仍与配置一致。

项目约定不新增单元测试或 Android 仪器测试。
