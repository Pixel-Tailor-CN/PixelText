# Issue #16：设置与 SMS 备份恢复设计

日期：2026-09-22；代码基线：919de9e。本文描述待实现行为，不代表功能已存在。

## 已确认范围

- 首版仅 SMS，不含 MMS/附件、RCS、第三方备份兼容、云同步或定时备份。
- 短信去重合并，不清空原有短信；关键词及白名单取并集；选中的设置由备份覆盖。
- 支持密码加密与未加密导出，后者明确提示隐私风险。
- 用户通过系统文件选择器选择文件；应用不主动上传，文件选择器可包含用户自己的云盘。
- 设置、规则、SMS 可分别选择；相关放行、归档状态随 SMS 迁移。
- 备份源为 Pixel Text 自身数据，包括应用数据库快照、设置及主题文件；不复制系统短信数据库，不新增独立的 Provider 短信导出扫描器。SMS 备份前复用已有镜像同步，恢复时从隔离备份库读取并通过 ContentProvider 合并写回。

## 应用数据库快照

1. 选中 SMS 时复用现有镜像同步，完成一次新的 SMS 全量对账及对应增量脏记录处理，检查本次成功结果和 SMS 结构完整性。启动任务、预算让出或旧 complete 标记都不算本次完成。同步失败、无权限或取消时拒绝输出“完整 SMS 备份”，不静默使用旧镜像；SMS 就绪判定独立于 MMS，不为此下载彩信附件。
2. 在现有镜像同步锁及数据库读事务保护下捕获一致 SMS 视图，分批写入新建的暂存快照库，保留相关表结构与源版本。复用既有字段和 rawSnapshot，不建立另一套 Provider 导出链路。快照提交并关闭后再打包，不在整个压缩期间占用同步锁。
3. 只向干净的新库写入允许表/行：镜像保留 SMS 父子记录；spam 库保留选中规则及 SMS 对应放行；archive 库保留 SMS 可关联归档。排除 MMS 内容及 rawSnapshot、附件、同步状态、脏记录、清理/下载队列和分类缓存。不得先复制整库再仅 DELETE，避免未选内容残留在空闲页或 WAL。
4. 每个源库分别在一致读事务中取快照，不承诺跨库全局事务。用源消息身份和指纹验证关联，不能可靠对应的放行/归档不套用，记录跳过数量。快照库提交、checkpoint/关闭后验证单独主文件可读，不依赖外部 WAL/SHM；不得遗漏源库 WAL 中已提交数据。
5. 不备份系统数据库文件；备份前同步仍通过已有链路读取 Provider。保证同步后捕获的应用快照，不承诺外部应用并发修改下的系统实时事务快照。

## 文件契约 v1

使用 `.ptbackup` 扩展名的版本化 ZIP，固定条目：

```text
manifest.json
settings.json
databases/message_mirror.db
databases/spam.db
databases/conversation_archive.db
theme/<不含用户信息的资源标识>
```

未选类别不写入对应数据，无数据的数据库条目可省略；manifest 明确记录包含类别，缺失不等于空数据。manifest 含格式标识 `pixeltext-backup`、schemaVersion=1、应用版本、快照时间、SMS 同步完成时间、各数据库 user_version/受支持结构标识、条目长度、分类记录数和 SHA-256。容器与数据库版本独立管理。

SMS 包内 backupId 使用快照镜像 localId；旧 sourceId/threadId 只用于解析包内放行、归档关联，恢复后映射新 ID。spam.db 可同时承载规则及 SMS 放行状态，按所选类别读写，不因文件存在就恢复整库。

SMS 保留 address、body、date、dateSent、type、read、seen、status、locked、subject、replyPathPresent、serviceCenter 和可空的源 SIM 展示信息。必需字段读取失败必须报告，可选列按设备能力读取；null 与空字符串保持区分。

已收、已发、草稿、失败及出站 SMS 均导出。恢复出站/发送中消息时转为失败状态并计数，绝不启动发送；无地址草稿保持无地址。

Moshi 用于 manifest、设置和既有原始字段适配；SMS 保存在应用数据库快照，不另导出 NDJSON。恢复通过 Cursor 分批读取，按字段白名单构造 ContentValues，禁止将 rawSnapshot 所有列原样写回。

未知更高容器或数据库版本在业务写入前拒绝。支持的旧库通过明确的读取适配或在隔离副本中执行已注册迁移处理，不使用破坏性重建，不触发应用初始化、同步或业务回调。数据库结构变更须更新备份兼容矩阵；非法必需字段及枚举拒绝。

## 加密与文件安全

计划使用成熟 ZIP AES 库 Zip4j 的 AES-256/认证格式，不使用 ZipCrypto 或自定义密码学协议；实施时核验锁定依赖版本、许可证及 Android 兼容性。全部有效载荷条目连同 manifest 加密；ZIP 文件名和大小等元信息可能可见，不宣称隐藏全部元数据。

密码仅保存在操作内存，不写入 WorkManager Data、SavedStateHandle、日志或磁盘；加密导出需确认密码，提示遗失无法恢复。

导入先复制到私有暂存区，完整解密认证、校验条目哈希并验证语义后，才允许业务写入。错误密码、截断、篡改、未知条目、重复条目和路径穿越均拒绝。只接受固定白名单路径，不按 ZIP 路径任意解压。

数据库也属于不可信输入：容器校验后先只读检查版本、允许表/列/索引、完整性、外键和记录语义，拒绝意外视图、触发器、虚拟表和运行态数据，不执行文件提供的任意 SQL。必要迁移只操作另一份隔离副本，迁移后重新校验；全部校验通过前不写业务库或 Provider。

资源边界：manifest/设置每条目最多 4 MiB；单条 SMS 的文本及 rawSnapshot 负载最多 1 MiB；单个背景最多 32 MiB 并检查图片尺寸；最多 32 个条目；解压总量最多 4 GiB，SMS 最多 100 万条。超限报错，不截断后宣称成功。累计实际字节数而非信任 ZIP 声明，限制校验耗时并支持取消，检查快照、解密及可能的迁移副本所需空间。

未加密包的哈希仅用于检测损坏，不认证来源。临时明文仅放不参与系统备份的私有目录，完成/取消删除，重启清理遗留内容，不承诺闪存安全擦除。

## 去重与身份映射

匹配键为精确 address、body、date、规范化消息类型；采用有长度边界的确定性编码及摘要，命中后比较原字段。号码不做有损归一化；read/seen、旧 ID、SIM 不进入键。已存在消息的已读状态不被覆盖。

不能简单集合去重：同键消息可能是真实重复。按稳定顺序一对一匹配，保留备份中的同键数量，仅补足目标缺少的条数。临时索引落盘，避免全量常驻内存；维护 backupId → 目标消息 ID 的映射。重试重新查询 Provider，覆盖“写入成功、记账前崩溃”的窗口。

旧 SIM 只供展示，恢复使用无效/未知订阅标识；由 Provider 生成新消息和会话 ID，并查询实际 threadId。单条放行使用目标身份重算指纹，归档按目标会话生成。混合 SMS/MMS 会话的归档可能影响目标现有 MMS 的列表展示，预览需提示，但不迁移 MMS 内容。

不同设备若改写地址或时间，保守匹配可能产生重复；不为避免重复而误合并内容不同的消息。不承诺其他应用同时修改 Provider 时全局 exactly-once。

## 架构与执行

Compose 页面和 BackupViewModel 管理交互；Domain 定义模型、状态及仓库；Data 负责容器、应用库快照/版本适配、设置规则映射、Provider 写回和协调，Koin 注入。

备份流程：选择类别/位置/密码 → 复用镜像同步并确认 SMS 完整 → 应用库一致快照及设置/主题快照 → 校验 → 打包/可选加密 → 输出。

恢复流程：解包到隔离区 → 完整校验及必要的隔离迁移 → 预览/选择类别 → 权限及角色检查 → 获取互斥和恢复保护 → 规则合并 → 从备份库读取 SMS 并通过 Provider 去重写回 → ID 映射及状态恢复 → 设置应用 → 从目标 Provider 对账当前镜像及重建索引 → 结果确认/清理。

备份库始终是独立恢复源，不替换当前运行库、不注册到当前镜像同步器。否则新设备 Provider 不存在旧 sourceId 时，正常对账可能删除备份消息，旧任务队列也可能作用于错误目标。

仅设置/规则备份恢复不要求默认短信资格；SMS 备份前同步需读取权限，写回需读取权限及默认短信资格，每批复核。

首版同一时刻仅运行一个备份/恢复任务，应用作用域协调器执行 IO，页面旋转不终止。提示保持应用前台，不承诺退后台持续执行、进程死亡续传或后台自动重试；进度与结果跨页面重建保留。

### 自动删除与通知保护

- 恢复前持久化保护状态，并与验证码清理每个删除批次共用互斥边界，等待已开始的删除结束后才能首次写入。仅在 Worker 开始时检查布尔值不能消除竞态。
- 不经过 SmsReceiver、发送入口或会触发历史消息通知的 SpamDetectionWorker；使用无通知、无自动操作的分类/索引重建路径。
- 合并同步刷新，避免每条导入触发全量重建；真实新收信仍走正常入口。
- 进程死亡后保留恢复保护，下次启动提示未完成恢复，允许重新导入，或确认保留已恢复数据后结束保护，不能无提示永久停用清理。
- 保护覆盖导入、索引重建及结果确认。若验证码自动删除开启，结束保护前提示后续常规清理可能删除已过期验证码，并允许关闭该设置；不承诺永久豁免历史验证码。

## 失败与 UI 语义

设置页新增“备份与恢复”独立页面，包含类别选择、加密开关、密码、预览、进度、取消和结果；备份进度区分镜像同步、快照及文件输出，结果包含关联状态跳过数量。

校验失败零业务写入；执行阶段不承诺跨设置、Room、Provider 整体回滚。磁盘满、角色丢失、Provider 拒绝或取消时停止后续写入，展示新增、已存在、失败、未处理数量及已完成类别。规则与设置使用可检查持久化失败的仓库接口，不把异步 apply 当作成功证据。

取消不删除已恢复消息。错误信息不能包含正文和敏感路径。SAF 输出完整写入并关闭后才报告成功；失败尽力删除不完整文件，无法删除则提示手动清理。新主题资源成功提交配置后才能替换旧引用。

## 验证

遵循[编码与验证规范](../development/coding-and-validation.md)，不新增测试目录、依赖或单元测试任务。执行 Kotlin 编译和 Lint，使用合成脱敏数据真机验证：设置/主题往返、规则合并、短信数量与真实重复、重复导入、草稿/出站转失败、SIM 差异、错误密码/损坏/超限零写入、磁盘不足、取消/进程中断、并发清理及真实新收信。

快照专项验证：镜像落后/同步失败不能输出完整备份；WAL 已提交记录不丢失；并发写入下快照一致；库内无 MMS、任务或未选内容的空闲页残留；损坏/不支持版本拒绝；支持版本可隔离迁移；备份库不受当前同步清理影响；写回后当前镜像与 Provider 对账一致。

默认短信角色与 Provider 写入需真机验证；争取覆盖 API 31 与目标 Android 版本，缺少设备则明确未验证。只修改本任务相关入口，不更改系统备份策略。仅文档调整检查差异、引用及设计一致性，不运行构建。
