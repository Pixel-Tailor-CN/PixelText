# 验证码视图设计

## 背景

项目当前能够通过本地规则把单条短信解析为验证码卡片，但验证码仍分散在各个会话中。现有“归档”是会话级能力，不适合按消息类型聚合验证码：同一发送方可能同时发送验证码和其他重要通知，归档整个会话会隐藏不相关短信。

本功能新增独立验证码视图，以可重建的本地索引聚合所有已识别的 SMS 验证码。首期只建设验证码视图，不实现定时删除。

## 目标与范围

- 仅识别 SMS，不读取或解析 MMS。
- 展示系统短信库中仍存在的全部历史验证码。
- 按接收时间倒序，以月份为分页单位加载。
- 月份标题在列表跨月时显示，并具有吸顶效果。
- 验证码索引跟随规则变化重建，新短信按当前规则即时更新。
- 默认卡片不读取原始短信正文；用户切换到文本模式时再按需查询 ContentProvider。
- 不改变现有会话归档语义，不实现验证码自动删除。

## 首页与导航

外层 `AppNavigation` 继续负责首页、会话详情、搜索、归档、骚扰、设置等应用级页面。原会话列表入口改为首页容器，首页容器内部使用独立的嵌套 `NavHost` 管理两个子页面：

- `conversations`：现有会话列表。
- `verification_codes`：新增验证码视图。

首页容器的 `Scaffold` 提供 Material 3 底部导航栏，包含“会话”和“验证码”。底栏只存在于首页容器；进入会话详情、搜索、设置、归档或骚扰页面后自然消失，不通过路由字符串手动控制显隐。

应用默认进入“会话”。两个子页面分别保留滚动位置和 ViewModel 状态。验证码条目通过首页容器向外层导航传递 `threadId` 和地址，复用现有会话详情页面；返回后恢复验证码列表位置。外部通知 deep link 仍由外层导航直接进入会话详情。

在验证码根页面按系统返回键时先回到会话根页面；在会话根页面再次返回才退出应用。底栏暂不展示数量角标。

## 共享开始聊天按钮

现有“开始聊天”扩展悬浮按钮从会话列表提升到首页容器，由两个子页面共享并继续进入现有新建短信流程。

- 页面初始进入和切换底栏页面时显示图标与“开始聊天”文字。
- 当前子页面向下滚动超过阈值后收起为仅图标状态。
- 当前子页面向上滚动超过阈值后重新展开。
- 会话列表和验证码视图分别观察自己的 `LazyListState`，只向首页容器上报滚动方向。
- 展开与收起使用 Material 3 `ExtendedFloatingActionButton` 动画，过滤列表回弹和轻微手势抖动。

## 验证码索引

验证码索引是可随时重建的派生缓存，不是短信分类的永久事实。索引只保存结构化识别结果和分页、导航所需元数据，不保存原始短信正文。

每条索引包含：

- `message_id`：系统 SMS ID，和 `generation` 共同标识索引记录。
- `thread_id`：跳转原会话。
- `address`：联系人解析和会话跳转所需的发件人地址。
- `timestamp`：接收时间和倒序排序依据。
- `month_key`：按设备当前时区生成的月份键，例如 `2026-07`。
- `code`：验证码。
- `signature`：解析规则输出的业务签名，可为空。
- `rule_version`：识别时使用的规则资源版本。
- `generation`：索引代际。

索引数据库另存活动代际、最近完整扫描规则版本和最近增量校验信息。DAO 查询只读取活动代际，刷新过程中页面继续展示旧代际。

当前会话私有缓存只保存每个 `thread_id` 的摘要、最新时间和未读数，并未缓存单条短信，因此不与验证码索引联表。验证码页面直接读取轻量索引；只有用户请求原文时才查询系统 ContentProvider。

## 索引刷新

所有后台刷新通过唯一 WorkManager 任务串行化，避免应用启动、规则更新和新短信接收同时覆盖数据。

### 新 SMS

收到新 SMS 后立即使用当前规则解析：

- 命中验证码时写入当前活动代际。
- 未命中时删除同 `message_id` 的旧索引，保证规则或消息变化后不会残留错误结果。

### 应用启动

应用启动后在后台执行增量校验。规则版本未变化时读取系统 SMS 的 ID 和变化信息，补充新增项、更新变化项，并清理系统短信库中已经不存在的索引；不重复解析所有未变化正文。

### 规则更新和手动完整识别

规则资源版本发生变化，或用户选择“重新识别全部短信”时，完整读取所有 SMS 并生成新代际。扫描完成后以数据库事务切换活动代际，再清理旧代际。任务失败或中断时继续展示旧代际，下次重新执行，不暴露半套结果。

### 删除同步

应用内删除单条短信或会话时同步清理对应索引。短信被其他应用或系统删除时，在下次启动增量校验、下拉刷新或原文查询失败时清理索引。

## 按月分页

数据库先返回活动代际中可用的月份列表，按月份倒序排列。页面首次加载最新月份，滚动接近当前月份末尾时加载下一个月份。每个月内部按 `timestamp` 倒序。

UI 使用 `LazyColumn` 的 sticky header 显示本地化月份标题，例如“2026年7月”。分页单位是完整月份，不使用固定条数截断月份内容。刷新后保持当前可定位的消息或月份位置；若该项已被删除，则回退到最近位置。

## 卡片与原文按需加载

验证码卡片默认只读取 Room 索引，展示验证码、业务签名或发件人、接收时间，不查询短信正文。

卡片支持：

- 点击验证码区域复制验证码，不自动标记短信已读。
- 点击“显示原文”后按单个 `message_id` 查询 ContentProvider。
- 查询期间仅当前卡片显示局部加载状态，不阻塞列表。
- 查询成功后切换为普通文本；点击“显示验证码”恢复结构化卡片。
- 点击“进入会话”复用现有会话详情。

正文只保存在 `VerificationCodeViewModel` 的有容量上限 LRU 内存缓存中，首版容量为最近 30 条。卡片的验证码/原文展开状态按 `message_id` 保存。验证码页面、会话页面之间切换或进入详情再返回时，展开状态和正文缓存保留；首页容器销毁后释放。配置变化时通过 `SavedStateHandle` 恢复展开状态，正文按需重新查询。

如果原文查询发现系统短信已不存在，则移除索引并通过 Snackbar 提示“原短信已不存在”。其他读取失败保持验证码卡片，并提供重试。

## 页面状态与交互

- 首次索引尚未建立时显示初始化状态和说明。
- 索引刷新或完整重建期间继续展示旧数据，并显示轻量刷新提示。
- 下拉刷新执行增量校验。
- 页面菜单提供“重新识别全部短信”，触发完整重建。
- 没有验证码时展示专用空状态。
- 联系人名称通过现有联系人数据源解析；无法解析时展示发件人地址。
- 不显示验证码总数角标。

## 错误处理与一致性

- 未取得短信读取权限或应用无法访问 SMS Provider 时，页面显示可恢复的权限/角色提示，不清空现有活动代际。
- 完整扫描只有成功后才能切换活动代际。
- 相同 `message_id` 在一个代际中只能存在一条记录。
- 月份键使用索引生成时的设备时区；设备时区变化后，下一次完整重建重新计算月份归属。
- 索引中的地址、时间和识别结果仅保存在应用私有数据库，不上传网络。

## 验证

项目不新增单元测试。实现后使用以下方式验证：

- `./gradlew :app:compileDebugKotlin`
- `./gradlew :app:lintDebug`
- 使用脱敏短信样本验证命中、未命中和规则版本变化后的全量重建。
- 在 Mock 或真机上验证按月分页、月份吸顶、底栏状态保存和悬浮按钮动画。
- 真机验证新 SMS 即时入索引、原文按需读取、外部删除清理和会话跳转。
