# 统一消息编辑器设计

状态：用户已确认统一 SMS/MMS 编辑体验、系统相机拍照、应用内录音和首次彩信资费确认（2026-10-03）。本文为设计细化稿，不表示所有细节已经用户审阅或实现验收。

代码基线：`main` 的 `bda2c2a424c8f40a42ede1def942e857a7db490d`。遵循 [AGENTS.md](../../AGENTS.md) 和[编码与验证规范](../development/coding-and-validation.md)。任务拆解见[实施计划](2026-10-03-unified-message-composer-implementation-plan.md)。

本文调整[原 MMS 发送设计](2026-10-02-mms-sending-design.md)的编辑交互：取消独立工程表单和人工准备步骤，并新增拍照、录音能力；原发送底层的单人边界、运营商限额、持久接纳和未知结果保护继续有效。旧文档反映当时范围，不作为本轮自动执行的清单。

## 1 目标与范围

用户希望获得接近 Google Messages 的日常消息编辑体验，而不是把底层发送过程包装成表单。

### 已确认目标

- 一个会话内只有一套消息输入区；普通文字输入发送 SMS，添加附件后发送 MMS，明确移除全部附件后回到 SMS。
- 支持选择图片、视频、音频和普通文件；支持调用系统相机拍照，以及应用内录音、取消和试听。
- 附件就地预览、删除；不离开会话重新填写已经确定的收件人。
- 用户只点击一次发送；附件准备、大小检查由应用自动执行。
- 首次发送彩信确认可能产生运营商费用；后续发送按钮明确标识 MMS，不逐条重复费用弹窗。
- 原结果未知后的重发始终要求单独确认重复送达及收费风险，不被首次费用确认替代。

### 保持的边界

- 仅传统 SMS/MMS 和单个明确收件号码，不增加群发、CC/BCC、RCS。
- 不改变默认 MMS 发布开关，不把模拟器通过当作运营商上线验收。
- 不新增远程压缩、解析、消息上传或自建 MMS 网络传输。
- 音视频和普通文件继续受原件及运营商大小限制；本轮不增加视频转码、剪辑或后台录音。
- 不因为附件失败、取消导入或准备未完成而静默删除附件改发 SMS。

## 2 现状与复用边界

代码路径相对于 `app/src/main/java/vip/mystery0/pixel/text/`。

| 现状 | 本轮处理 |
| --- | --- |
| `ui/message/mms/MmsComposer.kt` 使用独立全屏表单，暴露收件人、主题、SIM、PDU 字节数、准备与确认按钮 | 替换为统一编辑组件，工程细节不再占据正常发送界面 |
| `ui/screen/ConversationDetailScreen.kt` 同时持有 SMS 输入和另开的 MMS 编辑会话 | 合并用户可见的编辑入口，避免两份正文、重复草稿及互相清空 |
| `viewmodel/MmsComposerViewModel.kt` 已有持久草稿、版本检查、导入和准备能力 | 复用并编排为单次提交命令，不绕开原来的 revision 校验 |

| `ComposeSmsActivity` 接收系统编辑和分享入口 | 使用相同编辑组件，不回退到旧表单，也不因 Intent 到达自动发送 |

## 3 方案选择

| 方案 | 结论 |
| --- | --- |
| 只美化现有全屏彩信表单 | 无法消除 SMS/MMS 割裂、重复确认和手动准备步骤，不采用 |
| 会话底部统一编辑器，复用既有发送底层 | 满足交互目标，同时保留已验证的发送边界，采用 |
| 同时重写消息数据库、传输协调器和全部会话展示 | 扩大回归面，与本轮主要目标无关，不采用 |

## 4 页面与交互

### 4.1 统一输入区

底部使用 Material 3 圆角容器，组织为附件入口、可增长正文区与发送按钮。协议标识和当前 SIM 保持紧凑，不再以大段说明占据编辑区。

空白状态发送按钮不可用；有文字且无附件时标识 SMS；有附件时标识 MMS。键盘展开后输入区仍可操作，附件预览不能把正文和发送按钮挤出屏幕。保持浅色、深色、Dynamic Color 和现有输入区自定义样式。

### 4.2 附件入口与预览

附件入口以底部面板展示照片/视频、拍照、音频、录音和文件。现有选择器能力继续复用，不新增宽泛存储权限。

| 类型 | 预览与操作 |
| --- | --- |
| 图片 | 缩略图、独立移除按钮；必要的压缩提示附着在该附件上 |
| 视频 | 视频缩略图或明确的视频占位，显示类型和大小 |
| 音频 | 紧凑音频卡片、名称、大小与试听/停止操作 |
| 普通文件 | 文件类型图标、名称、大小与移除操作，不伪装成图片 |

数量、格式和大小错误就地说明，并保留草稿。导入失败项必须能重新选择或明确移除，不能无声地只发送成功导入的子集。

### 4.3 拍照与录音

拍照调用系统相机，输出到应用私有临时文件；只有成功返回后才导入附件。取消拍照不改变原正文和附件。

录音由用户主动操作并按需申请麦克风权限。录制状态显示时长、取消及停止；结束后形成可试听的音频附件。录音仅在前台进行，页面离开或进入后台必须释放录音资源；权限拒绝、无可用设备和录制失败应给出可恢复提示，不能妨碍继续编辑文字。

临时采集文件与正式附件副本分开管理，导入成功后按引用关系清理。不得因取消新录音而删除既有附件。

### 4.4 发送与状态

首次 MMS 费用确认明确号码、所选 SIM 和可能收费，用户确认后记录本设备的知情选择。拒绝确认保留内容且不创建发送命令；该确认不作为可迁移的通用设置。

发送后在相应消息处呈现准备中、发送中、失败、未知或已发送状态。重试、恢复编辑、清理遗留文件等低频操作进入菜单或按需展开，不永久占据输入区。已发送不等同于已送达。

## 5 状态与组件职责

| 组件 | 职责 |
| --- | --- |
| 拟新增 `MessageComposer` | 渲染统一正文、附件、SIM、协议和提交操作；不承担网络发送 |
| 拟新增 `ComposerCapture` | 系统拍照、前台录音及资源释放；采集结果交给既有附件导入层 |
| `MmsComposerViewModel` | 提供一致的草稿状态和提交编排；串行处理编辑、准备与接纳 |
| 两个现有发送协调器 | 分别接纳 SMS/MMS 并持久处理回执；继续独立于页面生命周期 |
| 会话页及外部入口 | 提供收件人和初始内容，消费提交结果；复用同一编辑体验 |

草稿正文和附件由持久层管理，SavedState 保存必要身份和轻量 UI 状态。只有对应草稿版本被接纳后才能清空；后续新输入不能被旧提交结果清除。

附件、收件人或 SIM 改动必须使旧准备结果失效。快速重复点击、准备期间退出、旋转和进程恢复不得创建重复发送。历史草稿与外部 Intent 中的正文、主题、附件及重发来源必须明确处理，不允许为统一外观而静默丢字段。

## 6 异常与隐私

- 单原件、总附件、附件数量、像素和完整 PDU 限额沿用原发送实现与运营商政策。
- 没有有效 SIM、默认短信资格缺失、附件不可读或超限时不提交，保留可编辑内容。
- UNKNOWN 不自动重发，首次费用确认不能消除其重复风险确认。
- 不记录原始短信或音视频内容到日志；验证使用合成数据。
- 新增 `RECORD_AUDIO` 权限后，仍须核对默认短信资格相关的 Manifest 入口。

## 7 验收标准

1. 一套输入区完成文字、添加附件、移除附件及协议切换，不再出现人工“准备附件并检查彩信”步骤。
2. 图片、视频、音频和文件有可辨识的预览；键盘、深浅色和旋转状态下布局可用。
3. 拍照成功/取消、录音授权/拒绝/取消/停止/试听、退后台释放均有验证证据。
4. 第一次 MMS 发送有资费确认，后续正常发送不重复弹出；未知重发仍确认。
5. 原有草稿、外部分享和系统 SMS 编辑入口均回归，不静默丢弃内容或改变接收人。
6. 实际发送 SMS 及带附件 MMS，并核对接收端内容；分别记录真实发送、诊断注入和仅代码检查的范围。
7. Debug 构建和 Lint 通过。遵守项目要求，不新增单元测试、测试依赖或测试任务。
