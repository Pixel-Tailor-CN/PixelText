# 检索页面与筛选交互重新设计

## 范围与依据

本设计替代已放弃的 2026-08-31 联系人与会话聚合搜索方案。旧 PR #12 已关闭，远端分支已删除。以本轮用户确认的交互为准，不继承旧方案的会话分区、姓名检索或结果数量上限。

视觉参考为用户提供的 Gmail 搜索页截图：搜索框下方排列一行可横向滚动的筛选项。实现保持 Jetpack Compose、Material 3、Dynamic Color 和暗色模式，不照搬截图的固定颜色。

本设计先于实现修订，尚未修改本需求的应用代码。现有搜索页已有关键词、未读、单 SIM、彩信和联系人筛选原型，但仍通过 `observeAllMessages()` 在内存中过滤，不作为本设计的数据层实现依据。

**前置依赖已完成：** [完整消息镜像与同步底座](2026-09-06-message-mirror-design.md) 已提供 SMS/MMS 根记录、MMS 全部地址与文本派生索引、同步状态和独立消息详情。本设计直接以镜像库为检索数据源，不再实时扫描 Telephony。彩信自动下载设置归属前置需求，默认关闭。

## 已确认的页面行为

- 顶部为返回、关键词输入框、清空关键词；占位文案“搜索短信”。
- 输入框下方固定顺序：发件人号码、SIM 卡、结果类型、日期、未读。
- 前四项有向下箭头，未读没有箭头。每项始终可见，横向滚动查看更多。
- 应用中的条件使用选中态和对应标签，点击已选项重新编辑。
- 关键词匹配短信正文，以及彩信主题、全部纯文本与 HTML 可读文字；各筛选条件与关键词取交集。不搜索 SMS 主题、名片/日历结构化字段、文件名、HTML 标签或 SMIL 控制文本，不做图片 OCR。
- 统一展示短信和彩信消息，按时间倒序，保留正文关键词高亮。
- 点击消息进入所属会话并定位该消息，不增加会话结果分区。
- 空关键词且无有效筛选时显示引导；有筛选时允许不输入关键词直接查询。
- 检索本身不引入网络请求、姓名联想、拼音或历史记录；复用前置需求的镜像库，彩信下载配置归属前置需求。

## 实现方案

采用镜像库原生 SQL 检索，不继续沿用当前全量读取后在 Kotlin 中过滤的实现，也不在本次引入 FTS。

- `MessageMirrorRepository` 提供镜像检索接口，Room DAO 使用可观察的动态参数查询；查询直接组合关键词、号码、SIM、类型、日期和未读条件，并按 `timestamp DESC, localId DESC` 排序。
- `MessageRepositoryImpl` 保持页面侧门面职责，把镜像结果映射为现有 `MessageModel`，补充 SIM 名称并批量查询骚扰判定。搜索仍包含普通、归档和骚扰消息，骚扰判定只用于点击后的内容视图选择。
- 动态 SQL 只拼接受控条件结构，所有用户值均通过绑定参数传入。关键词中的 `%`、`_` 和转义符按普通字符匹配，不能获得 SQL 通配语义。
- 不设置结果数量上限，不先全量映射再筛选。本次不引入分页；如果实际数据量需要分页，另行设计可见行为和定位恢复。
- 镜像数据库从 v2 显式迁移到 v3，新增 SMS 规范化号码列，并把 SMS 与 MMS 查询号码统一为仅数字形式。Migration 内按本地标识分批读取已有 SMS 原始地址与 MMS 原始地址，调用与后续同步相同的 Kotlin 规则，通过绑定 UPDATE 回填；不使用有限次 SQL `REPLACE` 冒充通用归一化，不依赖 Provider 权限或后续对账才能查询旧数据。迁移不改写原始地址、源快照或附件引用。

## 发件人号码独立页

### 布局和操作

- 点击“发件人号码 ▾”进入独立全屏 Compose 页面，保留检索页关键词、筛选和列表状态。
- 顶部返回与号码输入框，使用电话键盘，支持粘贴、修改和清空；进入时回填已应用号码。
- 输入包含有效数字时，展示“查看与 138 相关的会话”这样的结果项，数字随输入更新。
- 点击结果项立即应用号码包含条件并返回检索页。该文案按用户要求保留，实际筛选消息列表。
- 提供“从联系人选择”入口；选择具体号码后立即应用并返回检索页。
- 已有号码条件时提供“清除号码筛选”，点击后清除并返回。
- 返回、系统返回均放弃未提交输入；取消系统选择器停留在号码页并保留草稿。
- 不再需要“完成”按钮，应用操作由结果项或系统选择结果完成。

### 匹配与标签

- 输入 `138` 匹配发件人号码中包含 `138` 的消息；不要求完整手机号，支持 `106`、`10086` 等短号。
- 号码归一化使用共享的纯 Kotlin 规则，入库和查询不能各自定义：候选号码保存仅数字形式，忽略空格、括号、连字符及其他非数字格式符。
- 比较方向为候选号码包含输入片段，不能反向包含；没有数字的输入不能生成查询条件或匹配全量数据。
- 纯片段不强制补足手机号，也不因为以 `86` 开头就裁剪；只有输入明确以 `+86`、`0086` 开头，或为 `86` 加完整 11 位国内手机号时，才额外生成去国家码别名。候选号码匹配任一非空输入别名。
- 镜像现状仅为 MMS 地址保存了 Android `PhoneNumberUtils.normalizeNumber()` 结果，SMS 没有规范化列，且该结果并不等同于本设计的仅数字与国家码别名语义。因此实现必须包含数据库迁移、SMS/MMS 回填和后续同步统一写入，不能声称直接复用既有字段即可满足要求。
- 手动输入的标签显示号码片段。系统选中号码可以显示联系人姓名，号码作为辅助信息；修改号码即清除原姓名。
- 本次统一使用号码包含语义，系统选中的完整号码亦作为完整片段查询。

### 最小权限

- 使用 `ACTION_PICK` + `CommonDataKinds.Phone.CONTENT_TYPE` 选择具体电话号码；仅读取返回 URI 的 `NUMBER`、`DISPLAY_NAME`。
- 不用联系人 ID 再查询整张 Phone 表，不请求 `READ_CONTACTS`，不为选号触发默认短信角色申请。
- 不在本页实现通讯录联想列表。联系人查找交给系统选择器，其搜索能力由设备联系人应用决定，不保证预填 `138` 或返回匹配列表。
- URI 授权只用于本次读取，不请求持久授权。号码与姓名只保留于当前检索状态，不新增通讯录缓存。
- 无处理程序、取消、无授权、无号码时保留草稿；失败提示“未能读取所选号码，请手动输入”，不追加权限。
- 仅移除搜索流程的权限申请，不删除其他功能仍需使用的全局联系人权限声明。

依据：[Android 官方电话号码选择说明](https://developer.android.com/guide/components/intents-common#PickContactDat)。官方明确选择具体联系人数据可获得临时读取授权，无需 `READ_CONTACTS`。

## SIM 卡

- 底部弹层显示当前激活 SIM 卡的名称与复选框，按卡槽顺序展示，不硬编码两张卡。名称重复时附加卡槽信息。
- 默认全不选。全不选和全选都表示不应用 SIM 条件；部分选中表示任一所选 subscription ID 匹配即可。
- 弹层保留草稿，底部“重置”“应用”。重置清空草稿；应用一次性提交并关闭；下滑、返回、点击遮罩均丢弃草稿。
- 全选提交时归一化为不限，包括历史停用 SIM 和未知 SIM 的消息；部分选择才限制当前选中的 ID。全选应用后不保留全选展示状态，再次打开弹层显示全不选。
- 未筛选标签“SIM 卡”；单张显示卡名，多张显示“SIM 卡 · N”。
- 复用 `SimInfoProvider` 与现有电话状态权限，不为打开筛选申请权限。无法读取时弹层显示“暂无可用的 SIM 卡信息”，允许清除已有条件。
- 页面恢复前台和打开弹层时刷新 SIM 列表。已有部分选择移除失效 ID，若没有剩余有效 ID 或已涵盖全部当前卡，则归一化为不限。

## 结果类型

- 底部弹层两项复选框：“短信”“彩信”，默认全不选。
- 全选和全不选均表示不限；只选短信或只选彩信才应用条件。
- 同样使用草稿、“重置”“应用”和取消丢弃机制。
- 标签分别为“结果类型”“短信”“彩信”。保留草稿的实际全选状态，仅将有效查询条件归一化为不限。

## 日期

- 底部弹层单选：“任意时间”“一周前”“一月前”“半年前”“一年前”。默认任意时间。
- 点击选项立即提交并关闭，不提供应用按钮。
- 语义是早于对应截止时间，而非最近一段时间；严格使用 `timestamp < cutoff`。
- 每次实际查询捕获一次设备时区下的当前时刻。一周前使用 `minusDays(7)`，一月前、半年前使用 `minusMonths(1/6)`，一年前使用 `minusYears(1)`；保留当时时分秒，不取当天零点。
- 查询期间固定截止时刻，避免 SMS/MMS 使用不同边界。月份与闰日按 `java.time` 日历运算处理。
- 不限标签“日期”，选中后显示对应选项，例如“一周前”。

## 未读

直接点击切换未读条件，立即查询；再次点击取消。标签始终为“未读”，无箭头，不打开弹层。

## 状态与查询

- ViewModel 持有关键词与已应用筛选；号码页和弹层独立持有可保存草稿，只有明确应用才提交。号码页作为搜索目的地内部的全屏子页面，共享同一个搜索 ViewModel，不创建第二个搜索状态实例。
- 关键词输入保留 300ms 防抖；筛选提交使用当时输入框中的最新关键词立即触发，不等待尚未结束的关键词防抖。取消边界必须位于防抖之前：每次原始输入变化立即使旧请求失效，再在最新请求内部等待 300ms。不能沿用 `combine(query.debounce(300), filters)`，否则等待期间旧结果仍可能写回，筛选也可能使用旧关键词。筛选提交同时取消待执行的防抖，避免稍后重复发起同一查询。
- 用请求代次与 `collectLatest`/`flatMapLatest` 保证只有最新请求可以发布加载、成功和错误状态；取消异常继续抛出，不显示为搜索失败。结果携带实际查询关键词，不能用输入框的新关键词高亮旧查询结果。
- SIM 使用 subscription ID 集合，类型使用 `MessageTransport` 集合，日期使用枚举。有效性判定和“全选/全不选等于不限”的归一化集中在模型逻辑，不在各组件重复判断。SIM 全选提交归一化为空集合；结果类型允许保留 `{SMS, MMS}` 展示状态，但生成有效查询条件时视为不限。
- ViewModel 在每次实际发起查询时，根据设备默认时区捕获一次当前时刻并把固定的 `beforeTimestampExclusive` 毫秒值传入数据层；同一个可观察查询后续因数据库失效重发时不能重新计算日期边界。
- DAO 使用 `@RawQuery(observedEntities = ...)` 或等效 Room 可观察查询，显式观察消息根表、SMS/MMS、地址、part、文本派生索引及结果投影需要的关联表；不能只观察根表而漏掉正文、号码或索引变化。动态 SQL 仅决定是否加入受控子句和占位符，关键词、号码别名、SIM ID、截止时间等全部绑定为参数。
- 未读、SIM、日期、类型与号码片段直接组合查询；不再实时扫描 Telephony，不把号码片段并入正文关键词。关键词使用转义后的 `LIKE ... ESCAPE` 条件，以字面量方式匹配 SMS 正文、MMS 解码主题（没有解码结果时才回退原主题）以及符合本节范围的 MMS 可读正文。不能把原始编码主题与解码主题同时当作两份可读内容。
- MMS 正文范围已确认：全部纯文本 part 和 HTML 去标签后的可读文字，包括不在当前展示主正文中的文本附件；不包含名片、日历结构化字段、文件名、SMIL/XML 控制代码或 HTML 标签/脚本。按 part 顺序检索和提取摘要，每条 MMS 仍只返回一次。
- 现有 `mms_text_index.searchableText` 混入名片、日历文字，且基于展示用 `selection.parts`，不能直接复用为本次检索全文。扩展现有文本派生机制，增加范围明确的搜索正文投影及就绪状态，保留现有摘要和展示消费者语义；所需列统一纳入 v2→v3 Migration，并提升派生索引版本。旧索引缺少新投影时标记待重建，不能把默认空串当作已生成的空正文。
- 搜索正文由应用级端侧索引任务生成，复用既有文本解码与 HTML 安全解析能力，不由输入事件逐条启动解析。索引必须覆盖全部符合范围的文本 part，记录实际未就绪或失败状态；已读、附件替换、part 改动等造成索引失效后不能继续使用旧文本。SQL 只消费版本及源代次匹配的投影，索引写入前复核源身份；不能每次 SQL 查询后再把全库载入 Kotlin 计算指纹。
- 主题在正文索引生成前也可查询；内联纯文本可以通过限定 MIME 的安全回退参与查询，但不能用对全部原始 part 的无差别 `LIKE` 掩盖索引未就绪。命中回退文本的结果也必须带有对应的可读摘要。
- 彩信文本、主题和地址条件使用 `EXISTS` 或同等去重方式，每条消息仅返回一次。时间在镜像导入时统一为毫秒，日期查询严格小于同一截止值；时间为空的消息在启用日期条件时不匹配。
- 搜索结果由 `MessageRepositoryImpl` 批量补充骚扰判定，使用与会话详情相同的分类来源和阈值，避免逐条读取分数；不以骚扰状态裁剪结果。观察骚扰库变化，不能仅在镜像变化后更新导航判定。SIM 名称只用于展示，不参与查询。
- 消息时间相同时以 `localId DESC` 稳定排序。不设上限不代表零成本：`LIKE '%片段%'` 通常不能利用普通 B-tree 索引加速，验收必须使用大量合成数据检查查询时延、取消响应和结果映射内存；不得把后台执行或 LazyColumn 当作数据库分页。
- 搜索页面同时观察镜像同步状态和检索文本就绪状态。镜像结构完整不等于 `mms_text_index` 已生成：关键词查询还须考虑派生文本缺失、版本失效、解码失败及本地文本附件尚未就绪。已有结果持续可见；存在影响当前查询的缺口时，零结果显示“当前未找到匹配消息，结果可能尚未完整”，不能宣告确定全空。
- 同步进度尚未首次读到、首次基础镜像未完成、消息结构不完整或消息源读取失败时，不能宣告确定全空。不能仅检查 `phase == COMPLETE`：普通后台对账或与检索无关的线程辅助表缺口不应使搜索永久处于加载态。
- 无关键词的纯筛选查询不等待 MMS 正文索引；关键词查询不等待图片、音视频等与文本无关的附件复制。待下载彩信只对已有主题等可读文本负责，不等待下载、不自动联网。
- 结果摘要必须来自实际命中的正文或主题；命中非首个文本 part 时也能看到相应片段和高亮，不能仅返回命中消息却展示不含关键词的默认摘要。
- 号码筛选使用 SMS 原始地址和 MMS FROM 地址，已发送等没有外部 FROM 的记录沿用通信对端语义使用 TO/CC/BCC；不把 insert-address-token 当号码，全部参与方仍保留在镜像中。
- 全部消息状态可查询，包括草稿、待下载与失败；无 thread 的结果使用独立消息详情入口，不导航到无效会话。关键词命中待下载主题不触发下载。
- 首次镜像未完成时展示同步进度和“结果可能尚未完整”，不能以部分数据判定全空；附件复制不阻塞已有正文检索。
- 保留既有搜索可见性，不因筛选新增归档或骚扰排除。点击消息沿用现有骚扰内容视图选择。
- 不新增静默截断或继承旧方案的 100 条上限。若需要分页，应单独明确行为，不能先截断再按号码筛选。
- 引导文案“输入关键词，或使用筛选条件查找消息”；空结果“没有找到符合条件的消息”。
- 本次不新增长期保存搜索条件；旋转与打开号码页/弹层应保留当前会话中的输入、草稿、子页和列表滚动状态。列表状态提升到搜索目的地层，避免条件渲染卸载列表后重建丢失位置；返回详情后保留搜索条件及位置，新有效查询则回到结果顶部。系统返回在号码页优先取消草稿并回搜索页，在弹层优先关闭弹层，不能直接退出整个搜索。

## 消息定位

搜索结果继续使用现有兼容投影的真实 `message.id`：SMS 为源 ID，MMS 为 `-sourceId`，因此 `-1` 也可能是真实 MMS 消息 ID。

`conversation_detail` 路由已经使用可空字符串 `messageId`、缺省 `null` 并通过 `toLongOrNull()` 解析，不再把任何负数作为缺省值，本次不重复改造该参数协议。

有有效 `threadId` 的 SMS 和 MMS 都进入所属会话，并沿用按 `message.id` 相等查找和继续加载历史消息的逻辑完成定位。只有 `threadId` 为空或无效的结果进入现有 `mirror_message/{transport}/{sourceId}` 独立详情。点击前根据搜索结果批量取得的骚扰判定选择 `NORMAL` 或 `SPAM` 内容视图，不能因搜索结果默认 `spamScore=-1` 把骚扰消息错误导航到普通视图。

## 验证

- 编译与 Lint；遵循项目要求，不新增或运行单元测试。
- 真机覆盖无联系人权限选号、多号码联系人、取消/失败返回、无 SIM 和多 SIM。
- 号码片段、国家码、格式符号、无数字、关键词交集；数据库从 v2 升级后既有 SMS/MMS 号码仍可查询。
- 关键词包含 `%`、`_`、反斜杠等字符时按字面量匹配，不扩大结果范围。
- SIM/类型零选、单选、全选、重置后取消、应用后重开；SIM 全选应用后重开为零选，类型全选应用后仍保留全选；无有效条件时须回到引导态。
- 日期早于/等于/晚于边界、跨月和闰日、SMS/MMS 单位差异、正文与主题重复命中。
- 非首个文本 part、独立文本附件与 HTML 可读文字可命中；HTML 标签/脚本、SMIL、名片/日历专属字段、文件名和 SMS 主题不命中；旧版混合文本索引不能造成超范围命中。
- 快速输入和连续切换条件不能展示过期结果，包括 300ms 等待期间旧请求完成、待防抖输入期间提交筛选、取消时抛异常；结果高亮与实际查询一致。
- 旋转、号码页返回、弹层取消和消息详情返回不丢条件及滚动位置。
- 镜像完成但 MMS 文本索引未生成、索引失效重建、正文读取失败、仅图片复制未完成、普通后台对账等状态正确区分；仅地址/part/文本索引/骚扰库变化也能更新结果或导航判定。
- 大量合成消息下检查无上限查询的时延、内存和取消响应；升级迁移验证原始字段与附件引用不变。
- SMS、负数 MMS（含 `-1`）点击定位，暗色与动态取色、长卡名、横向筛选栏、键盘避让与读屏标签。

## 代码边界

主要修改 `domain/repository/MessageRepository.kt`、`domain/repository/MessageMirrorRepository.kt`、`data/repository/MessageRepositoryImpl.kt`、`data/db/mirror/`、`data/repository/mirror/`、`data/repository/mms/`、`data/source/mirror/`、`ui/message/search/`、`di/AppModule.kt` 和 `ui/AppNavigation.kt`。号码归一化提取为共享规则，由镜像入库、迁移回填和查询输入共同使用，避免查询侧与入库侧各自定义语义。

独立的号码页、筛选栏与各弹层拆成小型 Compose 文件。系统电话号码选择使用 `ACTION_PICK` 与 `CommonDataKinds.Phone.CONTENT_TYPE`；返回 URI 的单次读取封装在 `data/source`，只查询该 URI 的 `NUMBER`、`DISPLAY_NAME`。UI 仅启动选择器、提交 URI 并消费结果，不申请联系人权限。

检索复用镜像数据库，不增加网络依赖或权限。数据库升级必须新增显式 v2→v3 Migration，并更新 Room 导出的 schema；禁止破坏性重建。
