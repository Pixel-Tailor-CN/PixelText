# 检索页面与筛选交互重新设计

## 范围与依据

本设计替代已放弃的 2026-08-31 联系人与会话聚合搜索方案。旧 PR #12 已关闭，远端分支已删除。以本轮用户确认的交互为准，不继承旧方案的会话分区、姓名检索或结果数量上限。

视觉参考为用户提供的 Gmail 搜索页截图：搜索框下方排列一行可横向滚动的筛选项。实现保持 Jetpack Compose、Material 3、Dynamic Color 和暗色模式，不照搬截图的固定颜色。

本次输出设计与实施计划，尚未修改应用代码。

**前置依赖已调整：** 用户追加完整消息镜像需求，本设计以 [完整消息镜像与同步底座](2026-09-06-message-mirror-design.md) 为数据源；先完成消息与已下载附件镜像，再实现检索。已确认的五项筛选交互保持不变。彩信自动下载设置归属前置需求，默认关闭。

## 已确认的页面行为

- 顶部为返回、关键词输入框、清空关键词；占位文案“搜索短信”。
- 输入框下方固定顺序：发件人号码、SIM 卡、结果类型、日期、未读。
- 前四项有向下箭头，未读没有箭头。每项始终可见，横向滚动查看更多。
- 应用中的条件使用选中态和对应标签，点击已选项重新编辑。
- 关键词匹配短信正文、彩信文本或主题；各筛选条件与关键词取交集。
- 统一展示短信和彩信消息，按时间倒序，保留正文关键词高亮。
- 点击消息进入所属会话并定位该消息，不增加会话结果分区。
- 空关键词且无有效筛选时显示引导；有筛选时允许不输入关键词直接查询。
- 检索本身不引入网络请求、姓名联想、拼音或历史记录；复用前置需求的镜像库，彩信下载配置归属前置需求。

## 发件人号码独立页

### 布局和操作

- 点击“发件人号码 ▾”进入独立全屏 Compose 页面，保留检索页关键词、筛选和列表状态。
- 顶部返回与号码输入框，使用电话键盘，支持粘贴、修改和清空；进入时回填已应用号码。
- 输入包含有效数字时，展示“查看与 138 相关的会话”这样的结果项，数字随输入更新。
- 点击结果项立即应用号码包含条件并返回检索页。该文案按用户要求保留，实际筛选消息列表。
- 提供“从联系人选择”入口；选择具体号码后立即应用并返回检索页。
- 已有号码条件时提供“清除号码筛选”，点击后清除并返回。
- 返回、系统返回均放弃未提交输入；取消系统选择器停留在号码页并保留草稿。
- 不再需要“完成”按钮，应用操作由结果项或系统选择结果完成。

### 匹配与标签

- 输入 `138` 匹配发件人号码中包含 `138` 的消息；不要求完整手机号，支持 `106`、`10086` 等短号。
- 复用现有号码归一化思路，忽略空格、括号、连字符，完整国内号码兼容 `+86`、`0086` 前缀。
- 比较方向为候选号码包含输入片段，不能反向包含；没有数字的输入不能匹配全量数据。
- 纯片段不强制补足手机号或裁剪开头的 `86`；仅对明确国家码或完整号码生成去国家码别名。避免归一化产生空串导致全部命中。
- 手动输入的标签显示号码片段。系统选中号码可以显示联系人姓名，号码作为辅助信息；修改号码即清除原姓名。
- 本次统一使用号码包含语义，系统选中的完整号码亦作为完整片段查询。

### 最小权限

- 使用 `ACTION_PICK` + `CommonDataKinds.Phone.CONTENT_TYPE` 选择具体电话号码；仅读取返回 URI 的 `NUMBER`、`DISPLAY_NAME`。
- 不用联系人 ID 再查询整张 Phone 表，不请求 `READ_CONTACTS`，不为选号触发默认短信角色申请。
- 不在本页实现通讯录联想列表。联系人查找交给系统选择器，其搜索能力由设备联系人应用决定，不保证预填 `138` 或返回匹配列表。
- URI 授权只用于本次读取，不请求持久授权。号码与姓名只保留于当前检索状态，不新增通讯录缓存。
- 无处理程序、取消、无授权、无号码时保留草稿；失败提示“未能读取所选号码，请手动输入”，不追加权限。
- 仅移除搜索流程的权限申请，不删除其他功能仍需使用的全局联系人权限声明。

依据：[Android 官方电话号码选择说明](https://developer.android.com/guide/components/intents-common#PickContactDat)。官方明确选择具体联系人数据可获得临时读取授权，无需 `READ_CONTACTS`。

## SIM 卡

- 底部弹层显示当前激活 SIM 卡的名称与复选框，按卡槽顺序展示，不硬编码两张卡。名称重复时附加卡槽信息。
- 默认全不选。全不选和全选都表示不应用 SIM 条件；部分选中表示任一所选 subscription ID 匹配即可。
- 弹层保留草稿，底部“重置”“应用”。重置清空草稿；应用一次性提交并关闭；下滑、返回、点击遮罩均丢弃草稿。
- 全选提交时归一化为不限，包括历史停用 SIM 和未知 SIM 的消息；部分选择才限制当前选中的 ID。
- 未筛选标签“SIM 卡”；单张显示卡名，多张显示“SIM 卡 · N”。
- 复用 `SimInfoProvider` 与现有电话状态权限，不为打开筛选申请权限。无法读取时弹层显示“暂无可用的 SIM 卡信息”，允许清除已有条件。
- 页面恢复前台和打开弹层时刷新 SIM 列表。已有部分选择移除失效 ID，若没有剩余有效 ID 或已涵盖全部当前卡，则归一化为不限。

## 结果类型

- 底部弹层两项复选框：“短信”“彩信”，默认全不选。
- 全选和全不选均表示不限；只选短信或只选彩信才应用条件。
- 同样使用草稿、“重置”“应用”和取消丢弃机制。
- 标签分别为“结果类型”“短信”“彩信”。保留草稿的实际全选状态，仅将有效查询条件归一化为不限。

## 日期

- 底部弹层单选：“任意时间”“一周前”“一月前”“半年前”“一年前”。默认任意时间。
- 点击选项立即提交并关闭，不提供应用按钮。
- 语义是早于对应截止时间，而非最近一段时间；严格使用 `timestamp < cutoff`。
- 每次实际查询捕获一次设备时区下的当前时刻。一周前使用 `minusDays(7)`，一月前、半年前使用 `minusMonths(1/6)`，一年前使用 `minusYears(1)`；保留当时时分秒，不取当天零点。
- 查询期间固定截止时刻，避免 SMS/MMS 使用不同边界。月份与闰日按 `java.time` 日历运算处理。
- 不限标签“日期”，选中后显示对应选项，例如“一周前”。

## 未读

直接点击切换未读条件，立即查询；再次点击取消。标签始终为“未读”，无箭头，不打开弹层。

## 状态与查询

- ViewModel 持有关键词与已应用筛选；号码页和弹层独立持有草稿，只有明确应用才提交。
- 输入保留 300ms 防抖，筛选提交立即触发。新输入或筛选变化使旧请求失效，旧结果不能覆盖新状态。
- 主页面与号码页共享搜索 ViewModel，可在搜索目的地内部切换全屏子页，避免新建另一个状态实例。
- SIM 使用集合，类型使用集合，日期使用枚举。有效性判定集中在模型/领域逻辑，不在各组件重复判断。
- 数据层在后台查询本地镜像库，使用参数化条件。未读、SIM、日期、类型与号码片段直接组合查询；不再实时扫描 Telephony，不把号码片段并入正文关键词。
- 彩信按全部文本 part 或主题匹配，使用 EXISTS 或同等去重方式，每条消息仅返回一次。时间在镜像导入时统一为毫秒，查询严格小于同一截止值。
- 号码筛选使用 SMS 原始地址和 MMS FROM 地址，已发送等没有外部 FROM 的记录沿用通信对端语义使用 TO/CC/BCC；不把 insert-address-token 当号码，全部参与方仍保留在镜像中。
- 全部消息状态可查询，包括草稿、待下载与失败；无 thread 的结果使用独立消息详情入口，不导航到无效会话。关键词命中待下载主题不触发下载。
- 首次镜像未完成时展示同步进度和“结果可能尚未完整”，不能以部分数据判定全空；附件复制不阻塞已有正文检索。
- 保留既有搜索可见性，不因筛选新增归档或骚扰排除。点击消息沿用现有骚扰内容视图选择。
- 不新增静默截断或继承旧方案的 100 条上限。若需要分页，应单独明确行为，不能先截断再按号码筛选。
- 引导文案“输入关键词，或使用筛选条件查找消息”；空结果“没有找到符合条件的消息”。
- 本次不新增长期保存搜索条件；旋转与打开号码页/弹层应保留当前会话中的输入及状态。

## 消息定位

搜索结果传递真实 `message.id`。彩信使用 `-mmsId`，包括 `-1` 都可能是真实 ID。

路由将可选 `messageId` 改为可空字符串参数，缺省 `null`，再用 `toLongOrNull()` 解析；不再占用任何负数作为消息缺省值。详情沿用按 `message.id` 相等查找和加载历史消息逻辑。

## 验证

- 编译与 Lint；遵循项目要求，不新增或运行单元测试。
- 真机覆盖无联系人权限选号、多号码联系人、取消/失败返回、无 SIM 和多 SIM。
- 号码片段、国家码、格式符号、无数字、关键词交集。
- SIM/类型零选、单选、全选、重置后取消、应用后重开；无条件时须回到引导态。
- 日期早于/等于/晚于边界、跨月和闰日、SMS/MMS 单位差异、正文与主题重复命中。
- 快速输入和连续切换条件不能展示过期结果；旋转与返回不丢条件。
- SMS、负数 MMS（含 `-1`）点击定位，暗色与动态取色、长卡名、横向筛选栏、键盘避让与读屏标签。

## 代码边界

主要修改 `domain/repository/MessageRepository.kt`、`data/repository/MessageRepositoryImpl.kt`、`data/db/mirror/`、`data/repository/mirror/`、`ui/message/search/` 和 `ui/AppNavigation.kt`。号码归一化复用前置镜像生成的号码形态，避免查询侧与入库侧各自定义规则。

独立的号码页、筛选栏与弹层拆成小型 Compose 文件。系统选中 URI 的读取封装在 data/source，UI 仅启动选择器和消费返回值。检索复用镜像数据库，不增加网络依赖或权限。
