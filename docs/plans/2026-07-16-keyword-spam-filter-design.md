# 关键词骚扰拦截设计

## 背景与目标

Pixel Text 当前使用本地模型识别骚扰短信，但公益通知、信用卡账单提醒等内容可能只对特定用户构成干扰，也不适合上传为公共训练样本。关键词拦截为用户提供完全本地、可解释的个人规则：SMS 正文命中任意自定义关键词时，该短信统一视为骚扰短信，并复用现有骚扰通知和自动处理配置。

## 功能范围

- 仅匹配 SMS 正文，不处理 MMS。
- 关键词保存前去除首尾空格，使用不区分大小写的包含匹配。
- 不支持正则表达式、通配符或组合条件。
- 空关键词和忽略大小写后重复的关键词不能保存。
- 用户可以在独立管理页面新增、编辑和删除关键词。
- 新增或编辑关键词时明确提示：包含该关键词的短信将被标记为骚扰短信，并按照当前骚扰短信配置处理。

## 数据模型

关键词规则现在存于 `MessageMirrorDatabase` 的 `blocked_keyword` 表；命中规则 ID、原始模型分数、人工纠正、放行来源及最终 `isSpam` 存在 `mirror_message`。旧 `spam.db`、`keyword_spam_match` 和 `spam_result` 为历史迁移来源，不再是运行期写入目标。详见[主库合并方案](2026-11-05-main-database-consolidation.md)。

## 统一骚扰判定

`SpamRepository` 和主库 DAO 统一持久化最终判定，优先级为白名单／持久放行、关键词、当前消息人工纠正、有效个人／基础模型结果。关键词不伪造模型原始分数；删除关键词后重新按剩余规则、纠正与模型结果计算，不保证一定恢复普通状态。

骚扰页、消息级隔离、未读徽标及 Smartspacer 读取同一最终判定。关键词只匹配 SMS；显式放行优先于关键词。

## 新短信处理

收到 SMS 后，`SpamDetectionWorker` 同时执行关键词匹配与模型识别：

1. 使用当前关键词快照匹配短信正文并写入或清除该消息的关键词命中。
2. 在模型识别开启时继续运行模型并保存原始分数；关键词命中不跳过模型。
3. 最终副作用前重新核对消息身份、模型／学习代次及当前规则，按统一优先级计算骚扰状态；不能只对关键词和分数取逻辑或。
4. 最终命中时复用现有的“骚扰短信不提醒”和“骚扰短信自动执行”配置。
5. 自动已读或删除只作用于新收到的短信，不因历史索引重建批量处理旧短信。

即使模型识别开关关闭，关键词规则仍然生效；该开关只控制模型能力。设置页的相关文案会说明这一边界。

## 历史索引重建

关键词新增、修改、删除在学习决策锁和镜像同步锁保护下，将规则与现有镜像消息的关键词投影在同一主库事务提交。操作返回时，已有消息标记已更新，失败不会单独提交半套规则／投影。

管理页随后安排 `KeywordSpamRebuildWorker` 核对系统 SMS 快照：仅同步缺失或正文／会话发生变化的镜像，再事务重建投影并通知 Smartspacer。调度器使用唯一任务和 `ExistingWorkPolicy.REPLACE`；旧计划中的 `APPEND_OR_REPLACE` 已失效。后台重建失败保留最近已提交的数据，管理页提供重试；历史重建没有已读、删除或通知副作用。

## 界面设计

设置页在骚扰短信相关配置区域新增“关键词拦截”入口，摘要展示已配置数量。

关键词管理页使用 Material 3：

- 顶部应用栏标题为“关键词拦截”。
- 空状态使用现有插图与“还没有拦截关键词”；本地保存及不上传说明收进顶部信息弹窗。
- 非空状态使用列表展示关键词，点按编辑，尾部删除按钮用于删除。
- 右下角扩展 FAB 用于新增关键词。
- 新增和编辑使用输入对话框；仓库检查空值和大小写归一后的重复值，保存错误留在对话框。
- 重建期间在顶部显示线性进度提示和说明，不阻塞继续编辑。

## 错误处理与隐私

- 数据库写入失败时不关闭编辑对话框，并向用户显示错误。
- 后台重建失败时保留已提交的规则与消息投影，页面提供重试入口。
- 新短信关键词匹配异常时记录英文错误日志，并继续模型识别与原通知流程，避免吞掉短信通知。
- 关键词、短信内容和命中结果仅保存在设备本地，不参与 Hub 更新、样本上报或网络请求。

## 验证

- 编译 Debug 版本并运行 Lint。
- 在模拟器新增、编辑、删除关键词，验证校验、警告文案和列表状态。
- 使用现有 SMS 内容创建命中规则，验证历史短信进入骚扰列表；删除规则后，模型未命中的短信恢复。
- 验证新短信命中后复用静默、已读或删除配置。
- 验证 MMS 不参与匹配。
- 验证首页未读徽标、消息级骚扰隔离和 Smartspacer 使用统一结果。
