# 关键词骚扰拦截设计

## 背景与目标

Pixel Text 当前使用本地模型识别骚扰短信，但公益通知、信用卡账单提醒等内容可能只对特定用户构成干扰，也不适合上传为公共训练样本。关键词拦截为用户提供完全本地、可解释的个人规则：SMS 正文命中任意自定义关键词时，该短信统一视为骚扰短信，并复用现有骚扰通知和自动处理配置。

## 功能范围

- 仅匹配 SMS 正文，不处理 MMS。
- 关键词保存前去除首尾空格，使用不区分大小写的包含匹配。
- 不支持正则表达式、通配符或组合条件。
- 空关键词和忽略大小写后重复的关键词不能保存。
- 用户可以在独立管理页面新增、编辑和删除关键词。
- 新增或编辑关键词时明确提示：包含该关键词的短信将被标记为骚扰短信，并按照当前骚扰短信配置处理。

## 数据模型

在现有 `spam.db` 中新增两张表：

- `blocked_keyword`：保存关键词、规范化值、创建和修改时间。
- `keyword_spam_match`：保存命中的 SMS 消息 ID、会话 ID、命中规则 ID 和索引代次。

现有 `spam_result` 继续只保存模型原始分数，不使用伪造的 `1.0` 覆盖模型结果。有效骚扰判定为：模型分数达到阈值，或消息存在有效关键词命中索引。数据库升级采用显式 Room Migration，保留现有模型识别结果。

## 统一骚扰判定

`SpamRepository` 对外继续提供消息级和会话级骚扰查询，但内部将模型结果与关键词命中结果合并。以下功能自然获得一致结果：

- 骚扰短信页面。
- 隐藏完全骚扰会话。
- 首页未读徽标。
- Smartspacer 未读统计。
- 手动取消骚扰标记后的刷新逻辑。

关键词命中不修改模型分数，因此删除或修改关键词后，仍被模型识别为骚扰的短信会继续保留骚扰状态。

## 新短信处理

收到 SMS 后，`SpamDetectionWorker` 同时执行关键词匹配与模型识别：

1. 使用当前关键词快照匹配短信正文并写入或清除该消息的关键词命中。
2. 在模型识别开启时继续运行模型并保存原始分数；关键词命中不跳过模型。
3. 以“模型命中或关键词命中”计算最终骚扰状态。
4. 最终命中时复用现有的“骚扰短信不提醒”和“骚扰短信自动执行”配置。
5. 自动已读或删除只作用于新收到的短信，不因历史索引重建批量处理旧短信。

即使模型识别开关关闭，关键词规则仍然生效；该开关只控制模型能力。设置页的相关文案会说明这一边界。

## 历史索引重建

关键词新增、修改或删除后，安排唯一的 WorkManager 后台任务扫描全部现有 SMS。任务先使用关键词快照在内存中计算完整的新命中集合，再通过单个数据库事务替换旧索引，因此失败或取消时保留原索引，不出现中间清空状态。

连续编辑规则时使用替换策略，只保留最新一次重建请求。任务完成后刷新应用列表、未读徽标和 Smartspacer。历史重建不显示系统通知，仅在关键词管理页面展示“正在更新匹配结果”状态；失败时显示重试入口。

## 界面设计

设置页在骚扰短信相关配置区域新增“关键词拦截”入口，摘要展示已配置数量。

关键词管理页使用 Material 3：

- 顶部应用栏标题为“关键词拦截”。
- 空状态说明关键词仅保存在设备本地，并提供新增按钮。
- 非空状态使用列表展示关键词，点按编辑，尾部删除按钮用于删除。
- 右下角扩展 FAB 用于新增关键词。
- 新增和编辑使用输入对话框，实时校验空值与重复值，并显示醒目的影响说明。
- 重建期间在顶部显示线性进度提示和说明，不阻塞继续编辑。

## 错误处理与隐私

- 数据库写入失败时不关闭编辑对话框，并向用户显示错误。
- 重建失败时保留旧索引，页面提供重试入口。
- 新短信关键词匹配异常时记录英文错误日志，并继续模型识别与原通知流程，避免吞掉短信通知。
- 关键词、短信内容和命中结果仅保存在设备本地，不参与 Hub 更新、样本上报或网络请求。

## 验证

- 编译 Debug 版本并运行 Lint。
- 在模拟器新增、编辑、删除关键词，验证校验、警告文案和列表状态。
- 使用现有 SMS 内容创建命中规则，验证历史短信进入骚扰列表；删除规则后，模型未命中的短信恢复。
- 验证新短信命中后复用静默、已读或删除配置。
- 验证 MMS 不参与匹配。
- 验证首页未读徽标、隐藏完全骚扰会话和 Smartspacer 使用统一结果。
