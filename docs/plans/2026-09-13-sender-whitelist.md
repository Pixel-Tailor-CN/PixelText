# 发件号码白名单设计与实施计划

## 当前实现核对（2026-11-07）

匹配和历史永久放行语义仍保留，但存储已合入镜像库。依据 `SenderWhitelistRepositoryImpl.updateRules/allowedLocked`、`MirrorSpamDao`、`domain/spam/SenderWhitelistRepository.kt`：最多 500 条规则、单规则 256 字符；正则为 RE2/J 整串 matches，拒绝可匹配空串的表达式。保存/编辑/删除会核对历史身份，按 decisionMutex → 镜像锁 → 数据库事务提交，不另建旧 spam.db。

历史验收范围和未实测系统场景不因本轮文档核对而改变。

## 目标与确认边界
对应 Issue #13。精确完整号码和正则整串匹配原始发件号码，不做隐式国家码转换。设置页支持批量粘贴精确号码、编辑及删除规则、输入号码试匹配；会话提供添加当前号码的确认入口。
白名单覆盖模型、正文关键词和手动骚扰判定。新增规则回溯已有 SMS/MMS，不恢复已删除消息、不更改已读状态。已放行的消息永久保持非骚扰，编辑或删除规则只改变之后消息的匹配，不撤销既有放行。

## 架构与数据
- 原方案在 `spam.db` v2→v3 新增规则与放行表；当前已由 `MessageMirrorDatabase` v7 接管。`sender_whitelist_rule` 保存规则，`mirror_message.spamAllowedSource` 保存逐消息放行；`spam_allowed_message` 仅保留为备份 v1 的传输表。
- 规则表保存类型、表达式、更新时间；放行现为消息行字段，绑定 localId/revision，不保存独立放行操作时间，也不随规则外键级联删除。移出规则的历史命中转为 `RELEASED`，继续放行。
- Provider 的消息 ID 可能复用，写入/回溯前比较 ID、原始发件地址、date/date_sent 的身份摘要，并以 localId/revision 条件写入；身份变化或删除由镜像事务清理放行字段。摘要不含正文。
- 匹配规则使用 Domain 模型；正则采用 RE2/J 的线性时间匹配，避免恶意回溯表达式阻塞收信。界面明确不支持回溯引用和环视，限制规则长度并拒绝空匹配正则。
- `SenderWhitelistRepository` 统一管理规则、历史放行、有效消息放行和自动操作前的最终检查；规则变更与最终自动处理共用 Mutex。规则变更和受影响消息的放行在同一镜像库事务提交。
- `SpamRepository` 对全部读取返回有效状态；放行优先于模型分数和关键词命中。历史会话分页必须在过滤放行消息之后进行。
- 历史扫描、关键词增量和重建、详情单次识别在调用分类器前跳过已放行消息。后台模型执行中规则变化时，最终自动已读/删除/通知及落库再检查。
- 同步回溯在 IO 线程执行并显示保存状态，失败时事务回滚，不提示成功。保存、编辑及删除不得只排队后便丢失原规则匹配的历史消息。

## 实施步骤
1. 新增 Domain 规则/校验/仓库契约，Provider 身份读取、Room 表与迁移，实现原子规则修改及持久放行。
2. 接入 SpamRepository 统一查询、关键词增量/重建、实时检测、历史扫描、详情手动操作以及 Koin 注册。
3. 新增白名单管理 ViewModel、Compose 页面和编辑器；设置/导航/会话快捷添加接入。
4. 运行 `:app:compileDebugKotlin :app:lintDebug :app:assembleDebug`，检查 diff 和引用。按项目约定不新增或运行单元测试。
5. 模拟器覆盖升级迁移、精确与正则匹配、非法表达式、重复及批量输入、历史骚扰转正常、关键词冲突、自动删除豁免、移出规则后历史保留/新消息恢复拦截、会话快捷添加、重启和亮暗色显示。只使用独立合成样本，不读取或删除其他短信。

## 验收与限制
模拟器只能证明本地 SMS/合成 MMS、Room 和 UI 行为，不能代替运营商真实 MMS 收发或物理双 SIM 验证。日志与截图保存在忽略的 docs/.local。此次实现不自动提交。
