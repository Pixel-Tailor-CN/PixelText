# 自愿赞助入口设计与实施计划

## 已确认范围

采用 App 内展示官网收款码的方案。官网项目位于 `D:/WebstormProjects/website`，静态发布 `/support/config.json`。设置的「关于」增加「支持开发者」，进入原生 Compose 页面；提供支付宝、微信的收款码、保存图片和一键打开对应应用。支付链接仅在有效且受信任时使用，否则打开应用首页。赞助完全自愿，不提供数字权益，不接入支付 SDK、不记录支付状态。

相比直接跳转官网，本方案减少浏览器切换；相比 Play 内购，不新增商品、订单和权益系统。用户已选择并授权实施本方案。

## 数据契约

JSON 顶层字段为 `schemaVersion: 1`、`enabled: boolean`、`channels: array`。渠道包含 `id: alipay | wechat`、`enabled: boolean`、`qrCodeUrl: string`，可选 `paymentUrl: string`。渠道名称、应用包名、提示文案在 App 内固定。图片只接受官网 HTTPS `/support/` 下资源；支付链接按渠道限定 HTTPS 域名。未知字段可忽略，未知渠道跳过，缺失或类型错误的必填字段不猜测；无效支付链接只移除跳转增强能力。未知协议版本、格式错误、空响应与无有效渠道显示可重试失败；明确停用显示暂停状态。

## 实施与验收

1. 官网集中配置赞助资源，网页复用并静态生成 JSON；维护说明写入官网规范，运行 `pnpm check`、`pnpm build`，检查产出。
2. App 增加赞助模型、仓库、受限网络客户端和严格 JSON 解析。配置大小不超过 64 KiB，图片不超过 4 MiB，设置网络超时和取消传播；每个渠道独立失败，不影响其他渠道。
3. ViewModel 用 StateFlow 暴露加载、错误、停用、渠道与图片状态；页面支持重试、保存相册和打开对应应用。保存使用 MediaStore，不增加存储权限；启动失败只提示，不崩溃，不声称支付成功。
4. 补充 README 与隐私说明，执行 Kotlin 编译、Lint，核对 Manifest 默认短信入口保持兼容。按设备条件检查页面与错误状态，真实支付跳转需安装对应应用的真机确认。

不新增单元测试目录、测试依赖或运行单元测试任务，不自动提交、推送或部署。临时验证材料放在 `docs/.local/`。
