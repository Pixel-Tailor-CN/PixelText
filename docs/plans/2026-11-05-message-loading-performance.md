# 大数据量短信加载优化

## 目标与方案

针对约 7600 条短信、2100 个会话下的加载延迟，优化本地查询与重复处理，保持垃圾隔离、个人纠正、验证码和消息排序语义。沿用 Room、Flow 与现有仓库边界，不引入网络处理。

采用复合索引、轻量查询和批量读取；不通过关闭垃圾隔离或丢弃历史消息换取速度。数据库升级保留原有数据。

## 执行步骤

1. 为会话最新消息查询增加匹配线程和排序的复合索引，注册 Room 迁移。
2. 会话过滤只读取所需字段和指定会话，避免完整消息结构及 JSON 解码；彩信索引在查询层排除 SMS。
3. 个人纠正按消息键分批查询，保持精确身份匹配和白名单优先级。
4. 验证码指纹使用等价十六进制转换；减少不必要的全量核对写入，保证规则更新、删除和取消场景一致性。
5. 合并未读计数积压事件，保留设置变化触发重算以覆盖分类开关的依赖。
6. 检查历史消息定位和过滤分页，避免重复处理大量历史。

## 验收

- 编译、Lint、构建 Debug APK，不新增或运行单元测试。
- 对数据库副本比较摘要查询结果与执行计划；检查批量参数上限和复合键匹配。
- 模拟器覆盖安装，确认迁移成功、原有短信保留，检查首页、验证码、搜索与详情。
- 评审取消处理、规则版本变化、删除、新消息和白名单纠正语义。
- 性能记录、数据库副本与截图仅放在忽略目录；模拟器 Debug 结果不能视为真机 Release 性能。

## 首页即时展示补充

- 首页保留单一持续订阅，手动刷新与恢复前台推动镜像增量同步，不另起完整列表查询；归档表加入观察，积压输入合并。
- 模型身份、学习修订和参数代次由后台识别批次复核；列表读取不再运行分类或计算正文指纹。
- 首页必须展示实时查询结果，不使用磁盘列表快照或旧数据预览。
- 首次订阅先完成新消息增量同步；同步未完成时重试，不能发布旧镜像作为本轮结果。
- 隔离开启时直接按 `mirror_message.isSpam` 过滤：正常及未识别消息进入普通列表，骚扰消息进入骚扰列表；数据库汇总最新消息和未读数，不再加载候选正文重新判断。
- 分类写入时核验消息身份和修订号；正文或身份变化由同步链路清除旧判定并安排识别。最新彩信资料仍在会话查询事务内读取。
- 用分段计时定位实际数据读取、身份核验和评分开销，并验证进程退出期间的新消息能同步显示。

## 骚扰列表补充

- 骚扰列表直接读取持久 `isSpam=1`，不遍历正常短信，也不在开页时核验指纹、模型代次或规则。
- 按最新骚扰消息时间分组后分页。隔离开启时按骚扰消息汇总摘要和未读数；关闭时查询入选线程的完整摘要。
- 保留现有消息主键及会话复合索引；只有执行计划和耗时证明需要时才增加索引，不能用索引代替消除重复读取。
- Debug 页面计时从页面开始组合至首批内容就绪后的下一帧回调，不代表整个冷启动或精确的屏幕呈现耗时；日志仅记录页名、数量和耗时。

## 统一会话 SQL

- 首页、骚扰和归档使用统一查询参数表达可见消息范围，由 SQL 完成筛选、每线程最新行、未读汇总、排序与分页；先确定最终行，再关联需要显示的正文。
- 首页与骚扰页仅订阅相关表变化，避免为触发刷新先查询并丢弃完整摘要。
- `MirrorConversationQuery` 直接按持久字段表达范围：ALL 不加分类条件，NORMAL 保留 `isSpam=0` 或 NULL，SPAM 只保留 `isSpam=1`。消息修订和模型代次检查位于识别写入路径，不位于列表读取路径。
- 骚扰页未隔离时，仍先按骚扰消息确定会话页，再读取该页完整摘要；归档已改为关联当前消息、按最新消息时间排序分页，不再先分页归档 ID。保留各入口原有未读统计规则，时间相同以本地 ID 决定最新消息。
- 后续[持久判定方案](2026-11-05-persisted-spam-decision.md)和[主库合并方案](2026-11-05-main-database-consolidation.md)已替代早期候选校验方案：规则及最终 `isSpam` 存在主库，个人学习库仍独立；规则匹配和模型推理由写入及后台扫描更新，不新增磁盘列表快照。
- 搜索仅使用时间、SIM 等条件时跳过无用的彩信正文索引计数；广泛关键词的分页涉及全选、删除等语义，单独设计，不直接截断结果。
