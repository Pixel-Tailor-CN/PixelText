# 个人学习界面优化实施计划

## 目标与边界

将个人学习的纠正、管理、贡献流程改为一致的 Material 3 界面。采用已确认的底部纠正面板、摘要记录列表、两步贡献确认布局。使用主题颜色，支持深色、滚动、大字体和软键盘。

个人学习默认关闭；贡献草稿保留原文及来源提供的发送方，历史学习记录不补造发送方，由用户手动编辑或使用辅助脱敏。本地学习不自动上传。上传前必须完整展示实际提交内容、随附字段与用途，用户明确勾选并提交。保留现有分类优先级、持久化与重试语义，不改变模型和数据格式。

## 实施步骤

1. **会话内纠正**：`PersonalLearningScreen.kt` 与 `PersonalLearningViewModel.kt` 按单选再保存执行。首次开启在同一面板说明；保存成功关闭面板，以轻提示区分保存与更新。会话工具栏不保留醒目的上传入口，贡献可从菜单进入；纠正面板另有「同时贡献此样本」选项，选择后仅在保存纠正后打开待上传草稿，仍须检查内容并单独确认上传。
2. **个人学习管理**：总开关与真实状态置顶；学习记录采用连续列表，只展示两行摘要、分类和日期。详情以全文为主，通过分类行打开编辑对话框；删除收进更多菜单，贡献样本作为主要操作。清空与说明放入管理页更多菜单；不提供自动脱敏设置入口。失败文案不得虚构模型有效性；如需区分已有结果，最小扩展状态层提供真实信息。
3. **贡献流程**：修改 `SampleSubmissionScreen.kt` 及必要 ViewModel 接线，拆为检查内容和确认提交。草稿编辑、类别、可选发送方在第一步，第二步只读核对全文并完整告知附加字段和用途。复选框默认未选；返回修改后重新确认。保留待提交请求冻结与重试的幂等性，返回不上传、不影响本地学习。
4. **验证与交付**：检查累计差异；编译、Lint、构建 Debug APK；保留安装数据更新模拟器。使用合成短信走查纠正、管理、贡献确认、深色及大字体；不实际上传样本、不删除用户已有数据。截图和验证记录放在 `docs/.local/`。未覆盖的设备状态明确记录。

## 验收重点

- 选择标签不会立即学习；未选择时保存禁用，忙碌时防止重复执行。
- 初次启用明确说明本机保存和必要的基础识别开关；失败保留错误和可重试入口。
- 已保存不等于已生效；暂停、排队、更新、失败与有效结果文案准确。
- 长短信与大字体可滚动访问全部操作，正文不能因预览截断而无法检查。
- 上传同意不可预选，修改草稿后旧同意失效；完整保留字段、用途及本机样本库不上传的边界。
- 按项目约定不新增或运行单元测试；不修改权限、资产文件、模型协议，不提交或推送。

## 记录与上报入口调整

- “我的上报”移至设置的“骚扰识别与拦截”，与“个人学习”同级；删除关于分类和贡献设置面板里的重复入口。
- 关联短信数量不作为日常列表元数据；仅在修改或删除会影响多条相同内容短信时说明影响范围。移除列表和详情中的操作教学。
- 历史学习记录贡献前读取最新持久化分类，再进入既有草稿与确认页面；原记录不保存发送方和历史模型快照，不臆造来源字段。
- 上报列表以正文摘要、分类日期和审核状态为主，按月份分组；记录说明收进标题栏信息入口，仅保留一个贡献入口。待确认请求通过恢复行进入。
- 上报详情按审核结果、正文、分类时间组织，编号和其他低频信息收进信息弹窗；保留刷新、分页、限流重试及移除内容保护。
- 验收覆盖同级入口、设置图标、详情分类编辑与取消、贡献草稿、深色和大字体布局。无现有上报数据时，不为验证界面上传短信。
