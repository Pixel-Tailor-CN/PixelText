# 全应用界面一致性调整

## 目标

根据界面设计规范，逐页检查重复解释、操作优先级、Material 3 Expressive 色彩与空状态。保留现有原生组件、导航和业务边界，不新增上传或远程识别行为。

## 实施范围

1. 共享空状态：提取主页面既有插画样式为 `AppEmptyState`，统一会话、验证码、搜索、规则、学习和上报的无数据呈现。
2. 短信页面：检查首页、会话、归档、骚扰、搜索、验证码、MMS 内容与媒体、预览页。保留错误/权限/加载语义和短信发送确认。
3. 设置页面：检查各分类及通知、身份、外观、滑动操作、备份恢复、开源说明。移除常驻重复说明，把必要输入与选择放回对应功能区域。
4. 规则和学习：检查白名单、关键词、学习记录、贡献草稿、我的上报和详情。保留影响范围、不可逆与上传确认，去掉重复教学和竞争按钮。
5. 色彩：检查硬编码颜色、透明强调底色、容器与前景色配对；媒体、品牌和用户选色不机械替换。

## 验收方式

- 按页面登记检查覆盖及未改动原因，临时记录保存到 `docs/.local/`。
- 统一执行 Debug 构建和 Lint，不新增或执行单元测试。
- 保留数据安装模拟器，检查主要导航、插画空态、规则管理、贡献确认和可用预览；验证深色及大字体，结束后恢复设备设置。
- 不发送短信，不上传样本，不清空用户数据。需要真实上报、运营商或硬件的状态明确列出未验项。

本轮开始前已有学习与上报改动独立提交；本轮调整与它区分，便于审阅和回退。
