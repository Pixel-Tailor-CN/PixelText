# 完整消息镜像与同步底座设计

## 需求拆分

本需求为检索页面重设计的前置需求。先建立独立于会话页面的消息存储，再让检索读取本地库。现有页面结构暂不颠覆；未来可直接按消息、参与方、时间、解析结果组合数据。

用户已确认：

- 镜像所有可读取的 SMS/MMS，包括收件箱、已发送、草稿、发件箱、失败和排队状态。
- 归档与骚扰分类不影响收录范围。
- 已下载附件完整复制到应用私有目录，包括图片、音频、视频及其他 part；不只保存系统 URI。
- 尚未下载的彩信只记录待下载状态，镜像任务不自动联网下载。
- 取消新彩信无条件自动下载，设置提供“自动下载彩信”，默认关闭，由用户主动开启；支持手动下载。
- 系统消息确认删除后，删除对应本地消息和附件；权限丢失、查询失败不能视为删除。

## 现状结论

现有 `cached_conversation` 只有每个 thread 的摘要；`ConversationCacheRepository.fullSync()` 聚合系统消息后只存摘要，初始化还排除归档 thread。短信详情仍查询 Provider。彩信详情读取首个文本 part、一个地址与图片 URI，无法保留完整参与方与多媒体结构。验证码索引和骚扰库只存业务派生数据。

因此不能扩展现有摘要表来冒充完整镜像，也不能通过会话列表枚举消息：无有效 thread 的草稿、占位彩信等仍必须独立收录。

## 镜像定义与数据权威

镜像范围是当前 Android 用户/资料下、现有合法权限可读取的 Telephony 消息、会话和关联数据，不是拷贝系统数据库文件，不访问其他用户资料或不可读取的系统内部表。

系统 Provider 是消息收发与状态的权威来源。本地库保存可重建的完整读取副本；已读、删除、发送等先执行现有系统操作，成功后定向回读。分类、归档、主题等应用自有数据不写回系统，不被镜像更新覆盖。

“完整”分为消息结构已同步与附件内容已复制两项，不用一个 cacheReady 布尔值掩盖缺失。未下载内容不算复制失败；已下载但复制失败必须标记异常，不能谎报完整。

镜像不是备份或永久存档，不保留系统已删除消息作为可见历史。

## 存储模型

新增独立 Room 数据库 `message_mirror.db`，避免把可重建源数据与现有归档、骚扰、服务号资料混为一体。

### 消息标识

- 源标识为 `(transport, source_id)`，transport 为 SMS 或 MMS；两个 Provider 的 ID 不共用命名空间。
- 本地 `local_id` 为自动生成 ID，提供跨表关联。消息被确认删除后再出现相同源 ID，建立新的本地记录。
- 每条记录增加本地 `revision`，协调并发同步、附件任务与删除；旧任务必须校验 local_id 与 revision 才能回写。
- `thread_id` 可空或保留原值，是来源关联字段，不是消息主键或读取前置条件。原始无效值保留在源字段快照中。
- 现有 MessageModel 暂通过适配器保持 SMS 正数、MMS 负数。新数据库和同步层不使用负号编码或 `-1` sentinel。

### 表与职责

| 表 | 主要内容 |
| --- | --- |
| mirror_message | 源标识、本地标识、thread 关联、时间、SIM、原始箱类型、已读/已见、结构状态、revision |
| mirror_sms | 完整短信源字段快照与正文、地址、主题、发送时间、状态、错误、锁定等结构化字段 |
| mirror_mms | 完整彩信头快照与主题/字符集、PDU 类型、原始下载状态、事务/内容位置、过期/大小、解码后主题 |
| mirror_mms_address | 全部地址记录，保留源行标识、FROM/TO/CC/BCC 类型、字符集、地址原值及归一化号码 |
| mirror_mms_part | 全部 part，保留源 ID、顺序、MIME、字符集、名称、文件名、CID、位置、原始文本及字段快照 |
| mirror_attachment | part 关联、本地相对路径、源引用、字节数、摘要、复制状态、失败分类及重试信息 |
| mirror_thread_source | 系统可读取的 thread 行原始快照，包含系统摘要、参与方引用等，不作为消息读取依据 |
| mirror_canonical_address | Provider 可读取的参与方 ID 与地址映射，不读取系统通讯录 |
| mirror_sync_state | 各源集合的扫描代次、检查点、完整性、最后成功时间、错误类型 |
| mirror_sync_dirty | 去重的待回读源标识或集合失效标记，合并观察器与系统写入事件 |
| mirror_file_cleanup | 数据库事务提交后的待清理文件任务，独立于已删除消息行保存 |
| mms_download_request | 应用发起的下载请求令牌、源消息关联、临时 PDU 路径与持久化阶段；不属于 Provider 原始镜像 |

查询用字段建立强类型列；额外源字段用统一带类型快照保真，不能把所有业务逻辑建立在任意 Map 上。快照保留列名、Cursor 类型、null、整数、浮点、文本和 BLOB，整数不能经 Double 丢精度；未知列不静默丢弃。BLOB 使用可逆编码或本地文件引用。

运行时读取返回列集合并记录能力清单。源数据不可读与源字段值为 null 分开表示；可选列缺失不使整次导入失败，但必须暴露覆盖情况。原始 `_data` 等系统路径只作字段信息，读取附件使用授权 content URI，不越权访问该路径。

### 必须保留的数据

- SMS：现有正文、地址、SIM、时间之外，保留 `type`、`status`、`date_sent`、`read`、`seen`、`locked`、`error_code`、`subject`、`protocol`、`reply_path_present`、`service_center`、`creator` 及设备返回的扩展字段。不能把所有非收件箱压缩成一个 isReceived=false 后丢弃原类型。
- MMS：保留所有可读取头字段、所有地址和全部 part，不能只取 FROM 第一行或首个文本。保留原始编码信息与解码结果，SMIL 及内容 ID/顺序必须可用于后续重组。
- 同时保留原始时间及其单位，查询时间转换为毫秒；不覆盖原始值。
- 正文检索派生字段按 part 顺序生成。检索各文本 part 或主题时每条消息只出现一次，不能丢失非首个文本 part。
- 原始会话行若不可读，记录能力缺口；仍独立同步所有消息。系统会话快照用于诊断和保真，实际列表摘要可由本地消息计算。

## 附件复制与状态

文件保存到 `context.noBackupFilesDir/message-mirror/`，数据库仍使用 Room；备份规则显式排除数据库及其旁文件，并核对既有云备份和设备迁移配置。不上传源内容或哈希。

- 已下载且可读取的全部二进制 part 原样流式复制，保持字节内容，不转码、不压缩、不只复制缩略图。
- 文本与 SMIL 原值保存在 part 表；如果 Provider 另有可读取流，也保留流内容。不能假设所有 part 都有二进制流。
- 文件名由本地标识、revision 和随机令牌生成，不采用来源文件名拼路径；数据库存相对路径。
- 使用同目录临时文件复制，边读边计算 SHA-256 与字节数。读取完成、关闭流并完成必要落盘后，原子改名，再事务绑定 attachment；数据库绑定前重新核验消息仍存在且 revision 未变。
- 数据库与文件系统没有共同事务：改名后未绑定文件由孤儿清理回收；绑定后任务中断不重复覆盖 READY 文件。
- 附件更新时先完成新文件再切换引用，旧文件进入清理队列；记录不能长期把旧附件当成新 revision 的内容。
- 初版不跨消息去重，避免引用计数影响删除语义。

内容状态：`PENDING_DOWNLOAD` 表示源尚无已下载内容；`SOURCE_PRESENT` 表示可读内容待复制；`COPYING`、`READY`、`COPY_FAILED` 表示本地状态；源已下载但无法读取表示 `SOURCE_UNREADABLE`，不能当作待下载。

不能只凭没有 part 判定未下载：合法纯文本/空草稿、NotificationInd、失败发送等需结合原始 PDU 类型、part 状态判断；不认识的源状态保留 `UNKNOWN`，不编造成功。

空间不足时保留已同步文本和失败状态，停止重试循环，保留可续传任务（单个失败文件可以重头复制）。用户可见“部分附件尚未复制，可稍后重试”。不能为节省空间静默删除仍应镜像的 READY 附件。

## 首次导入

1. 注册变化观察并建立持久 dirty 队列；扫描期间新事件不能丢失。
2. 从 SMS/MMS 根集合读取所有箱类型，不依赖 thread 集合，不按归档或骚扰裁剪。
3. 分批键集扫描，每源以 source_id 为游标，初始批量 200。每批短事务 upsert 元数据与同批扫描检查点，禁止长事务跨 Provider IO。
4. 每个 MMS 独立读取全部地址与 part，成功后在单个事务中替换该消息子结构；子查询失败保留旧结构并标记不完整，不能把失败当空集合清理。
5. 会话与 canonical address 单独扫描；消息没有对应会话仍可导入。
6. 基础记录扫描后排空 dirty 队列，再做完整性对账；只有成功覆盖源集合才记录本轮完成。Provider 无跨表原子快照保证，存在竞争时继续收敛，不能宣称某一瞬间的绝对快照。
7. 附件复制以持久任务继续运行，核心文本读取不被大视频阻塞；源尚未下载部分保持 pending，不触发网络。

首次导入期间新本地页面显示同步进度和“结果可能尚未完整”，不将未完成误显示为“没有消息”。旧数据不先清空；已有镜像持续可读并标记同步状态。恢复检查点仅用于继续导入，不能据未完成扫描清理记录。

## 后续同步与删除对账

- 进程内观察 SMS/MMS，包括可捕获的 addr/part 变化；具体 URI 能解析为消息时定向回读，否则标记集合需对账。观察器是提示，不是可靠日志。
- 本应用收发、已读、删除、下载回调成功后追加 dirty 信号，仍以系统回读为最终值，避免双写漂移。
- 应用进入前台、权限恢复、首次初始化与手动刷新都安排补同步。WorkManager 使用唯一任务串行协调，并安排低频完整对账作为进程死亡后的兜底；不承诺实时后台运行。
- 完整对账检查所有旧记录状态与子结构，不能只扫描更大的 ID 或更晚日期；历史已读、草稿修改、旧附件替换都必须可更新。源不提供可信版本的附件，完整校验轮次需要读流校验摘要，不能永远信任“ID 和大小相同”。
- 所有写入由统一协调器串行化；本地 revision 防止陈旧任务复活删除记录或把新附件绑定到旧消息。

删除判据：

1. 成功遍历目标源集合得到本轮存在 ID，或在本应用成功删除后定向核查。
2. 仅对缺失候选做无额外过滤的存在性复查。null Cursor、异常、权限不足、截断、取消一律不是不存在。
3. 确认缺失后事务删除对应消息/子结构/派生记录，并把附件路径写入独立清理队列。
4. 事务提交后执行文件清理，失败保留队列重试。清理前验证路径仍处于私有镜像目录且没有现存引用。

系统有并发变化时只能保证最终收敛；发生新通知、权限变化或扫描完整性不确定时延后删除并重查。集合突然变空也必须满足同样验证，不允许异常分支 deleteAll。

系统库重建或 ID 复用不应按正文自动合并不同消息。已确认删除后同 ID 再出现使用新 local_id；没有可靠证据区分的变化当作源记录更新，不能声称可辨认所有系统重置场景。

## 写入与同步边界

镜像任务仅读取 Provider，不负责发送、下载或恢复消息。用户操作仍走现有 Telephony 写入路径；系统操作失败时保留镜像并显示失败，不提前永久删除本地数据。

标记已读等操作可展示短暂处理中状态，真实持久状态以回读结果为准。镜像不可用时现有系统操作可继续，稍后补同步；不向本地写入伪造的系统消息 ID。

## 彩信下载策略与设置

用户进一步要求取消现有新彩信自动下载，交由设置决定。本节属于镜像底座需求的接收适配部分，网络行为由独立下载服务负责，不能由镜像任务触发。

- 新增 `autoDownloadMms` 设置，默认 false；升级没有此键同样关闭。文案“自动下载彩信”，说明“开启后自动下载新收到的彩信，可能使用移动数据”。
- 关闭时接收器只保存 NotificationInd 占位、参与方和可用头信息，通知用户，状态是“待下载”，不能一插入就写“下载中”。
- 只有收到新通知且开关开启，或用户主动点击“下载”时，才交给下载协调器。开启设置不批量补下载历史待下载记录，前台恢复、搜索、同步和重试附件复制也不触发下载。
- 待下载卡显示“下载”；下载中禁用重复点击；失败显示“重试”；已过期、无有效 SIM 或缺内容位置时显示具体不可下载原因。用户手动下载不要求先打开自动下载设置。
- 关闭开关阻止后续自动启动；已交给系统的下载允许结束，不声称可强制撤销系统请求。
- 按源消息持久记录请求令牌，避免双击/重复 WAP Push/重入造成重复下载；用接收时 subId，不静默选择另一张卡。
- 下载完成不等于镜像完成。真实 PDU 必须被解析并正确写入系统 MMS 头、addr、part，再发 dirty 信号，镜像回读并复制附件。

现有 `MmsReceiver` 直接调用下载，`MmsDownloadReceiver` 主要更新状态，不能据回调成功断言系统已拆解所有 part。官方 `downloadMultimediaMessage` 约定输出的是指定 URI 上的 PDU，需要核实并补齐本应用的解析/持久化链路，不能仅沿用现有注释。参见 [SmsManager](https://developer.android.com/reference/android/telephony/SmsManager)。

实现使用应用控制的临时 PDU 输出 URI 和精确授权，解析后持久化到 Provider；不添加广泛文件访问权限，不依赖隐藏 API 反射。当前 `WapPushPduParser` 只处理通知，不能冒充 RetrieveConf 解析器。下载故障恢复、解析失败、部分写入清理必须与占位记录关联，避免生成重复会话和消息。持久化完成后才将源状态标为已下载；若先前进程中断，恢复任务依据令牌和源状态幂等续作。

## 当前页面接入与后续重组

第一阶段保持现有仓库接口和页面层级，替换核心列表/详情数据读取：

- MessageRepository 的消息详情读取从 mirror_message 及子表获取，图片指向私有副本。
- 会话摘要由镜像消息聚合形成兼容投影，使用原 threadId 保持现有导航、归档和主题行为；不把摘要表作为详细消息的父实体。
- 旧 ConversationCacheDatabase 暂保留服务号表，摘要缓存可过渡清理；不得删除服务号资料。
- 验证码、骚扰分数等保留为业务派生数据；既有独立后台扫描暂不要求全部改写，但核心页面不能混用两个详情来源。
- 新的底层接口支持按消息 ID、号码、时间、类型直接读取；无 thread 的记录也能获得完整详情。未来群组重组不受当前 ConversationModel 单地址限制。
- 新检索页使用此底座。草稿/无有效 thread 的结果至少支持独立消息查看，不能导航到 thread=-1；不在本次增加草稿发送编辑器。

过渡适配器不应丢弃附件模型：保留全部附件给未来 UI，现有图片卡只消费图片子集。音频/视频播放界面升级不属于完整镜像验收，但内容与元数据必须已保存且可读。

## 验收与完成定义

- 对设备可读取源集合逐项比对记录 ID 和原始字段；所有状态都纳入，不能只核对收件箱数量。
- MMS 比对所有地址、所有 part、顺序、原始文本；图片/音频/视频/其他已下载文件逐一核对字节数与摘要。
- pending 不联网；copy_failed/source_unreadable 不标 READY；附件失败不阻止可读正文。
- 改已读、草稿、发送状态和旧 MMS part 后可收敛；消息和附件删除一致。
- 杀进程、取消扫描、撤销权限、磁盘满、null Cursor、扫描期间新增/删除/下载完成均不误删、不串附件、不丢检查点。
- 日志仅计数、阶段和错误类型，不含号码、正文、附件名、URI 或内容摘要。
- 编译、Lint、真机核验；不新增或运行单元测试。未有真机证据的覆盖项明确标记未验证。

## 官方结构依据

SMS 状态与字段参见 [TextBasedSmsColumns](https://developer.android.com/reference/android/provider/Telephony.TextBasedSmsColumns)；MMS 头参见 [BaseMmsColumns](https://developer.android.com/reference/android/provider/Telephony.BaseMmsColumns)。

MMS 的地址与内容组成独立结构，参见 [Mms.Addr](https://developer.android.com/reference/android/provider/Telephony.Mms.Addr) 和 [Mms.Part](https://developer.android.com/reference/android/provider/Telephony.Mms.Part)；会话源字段参见 [ThreadsColumns](https://developer.android.com/reference/android/provider/Telephony.ThreadsColumns)。具体列以设备实际可读取结果为准。
