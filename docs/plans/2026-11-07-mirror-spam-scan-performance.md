# 镜像短信识别性能优化

## 目标与边界

历史重识别只以镜像表为输入，不读取系统短信 Provider、不触发镜像同步；系统与镜像的差异由既有同步链路处理。初始化已经有独立镜像阶段，识别阶段复用同一批处理路径。保持全部 SMS 的既有扫描范围，不扩展至 MMS。

进度更新与识别隔离，每批完成或每秒由独立协程上报最新快照；合并积压更新，上报失败不使识别失败。仅在任务结束时等待最后一次进度发布，取消沿用任务取消语义。

## 设计

- `MirrorSpamDao` 增加轻量联表投影、按 localId 分页和批量保存。固定本轮 localId 上界；模型版本、学习代次和消息 localId／revision 均参与过期检查。
- `MirrorSpamScanner` 负责镜像分页、规则快照及批次提交，替代逐条 Provider 校验与保存。每批在事务内重读当前规则和人工标记，以当前优先级计算最终结果；只更新分类字段。
- 每轮持有独立分类器和个人参数快照，提交批次时复核当前模型、设置及学习版本。发生变化则丢弃过期批次并重试，不长时间持有决策锁运行模型。
- `SpamClassifier` 增加会话快照入口；个人参数有效时直接进行个人推理，失败时恢复参数并回退公共模型，避免每条重复运行两个模型。
- `HistoricalSpamScanWorker` 负责调度、内容变化代次确认和通知，使用 `SpamScanProgressReporter` 非阻塞发布进度。只有完整成功的扫描确认内容代次，不能吞掉并发新增或修改的消息。
- 历史识别入口的数量统计也改为镜像表聚合，并使用当前模型／学习版本计算待处理数，避免打开统计框时读取全部系统短信。
- 历史推理最多并行两条，每条协程独占一个模型实例和内部两个计算线程，按可用 CPU 数降至单路。每批动态分配行，结果由单个汇总协程合并，保存仍为一次事务；初始化识别默认单路。模型切换、取消或初始化失败时关闭所有已创建实例，不共享解释器。
- 旧版判定迁移和中断投影恢复由独立的 `SpamDecisionPreparationWorker` 在启动时完成。扫描器只检查完成标记并重试等待，不能抢先写入导致旧放行／纠正无法迁移；也不能调用会访问 Provider 的原 `ensureReady`。

## 执行与验收

1. 实现镜像批处理读写与模型快照，保留白名单／放行、关键词、人工纠正、模型的既有优先级。
2. 接入历史扫描和初始化识别，移除识别链路中的 Provider 读取、镜像刷新及逐条 WorkManager 进度等待。
3. 接入独立进度合并器；添加仅含数量与耗时的英文性能日志，不记录短信正文或号码。
4. 执行 `:app:compileDebugKotlin :app:lintDebug :app:assembleDebug`，核对 Koin 注册和源码调用路径，不新增或运行单元测试。
5. 使用模拟器及合成短信检查批量扫描、重复扫描跳过、人工标记保留和任务进度；独立评审取消、规则修改、模型切换、消息删除／修改等并发边界。

真实 Pixel 上 7000 条短信的耗时、发热和后台运行表现需真机确认；模拟器耗时不作为手机加速比例。
