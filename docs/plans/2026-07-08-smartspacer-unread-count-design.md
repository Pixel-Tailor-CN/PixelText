# Smartspacer 未读数量统计范围设计

## 背景

当前 `Smartspacer` 未读数量直接按系统短信表中的未读收件箱短信数量统计，不区分普通短信、骚扰短信和归档短信。应用内主列表、骚扰拦截页、归档页的可见范围与 `Smartspacer` 计数口径不一致，容易让用户看到“应用里没有未读，但 Smartspacer 仍显示未读数量”的体验割裂。

## 目标

- 为 `Smartspacer` 未读数量增加可配置统计范围。
- 配置项仅影响 `Smartspacer` 未读数量，不影响点击跳转行为。
- 支持以下 3 个独立开关，默认全部开启：
  - 正常短信
  - 骚扰短信
  - 归档短信
- 统计口径按消息级别并集计算，同一条短信即使同时命中多个分类，最终只计数一次。

## 分类定义

- 正常短信：未读、非骚扰、未归档。
- 骚扰短信：未读、命中骚扰识别阈值。
- 归档短信：未读、所在会话已归档。

说明：

- “骚扰”和“归档”是可叠加标签。
- “正常短信”是互斥补集，只包含既不骚扰也不归档的未读短信。

## 统计规则

给定一条未读短信：

1. 先判断它是否属于归档会话。
2. 再判断它是否被标记为骚扰短信。
3. 最终计入条件为以下逻辑或：
   - 开启“正常短信”且该短信既不骚扰也不归档。
   - 开启“骚扰短信”且该短信被标记为骚扰。
   - 开启“归档短信”且该短信所在会话已归档。

当 3 个开关全部关闭时，`Smartspacer` 不显示未读数量。

## 数据来源

- 未读短信基础集合：系统 `Telephony.Sms` 收件箱中 `READ = 0` 的短信。
- 骚扰标签：本地 `spam_result` 表。
- 归档标签：本地 `archived_conversation` 表。

本次只调整现有 `UnreadSmsComplicationProvider` 的短信未读数量逻辑，不扩展到 MMS。

## UI 方案

在设置页新增一个首选项入口：

- 标题：`Smartspacer 未读统计范围`
- 摘要：根据当前开关状态动态展示，例如：
  - `统计全部未读短信`
  - `统计正常短信、归档短信`
  - `不显示未读数量`

点击后弹出对话框，提供 3 个开关：

- 正常短信
- 骚扰短信
- 归档短信

对话框内编辑临时状态，点击确认后统一保存；取消时不落库。

## 实现边界

- 不改 `Smartspacer` 点击后的跳转行为。
- 不改验证码 `Smartspacer` 目标卡片逻辑。
- 不新增单元测试，验证方式遵循项目约束，使用 Kotlin 编译检查。

## 联动刷新

由于未读数量将依赖骚扰标签和归档状态，以下变化后都需要通知 `Smartspacer` 刷新：

- 修改 `Smartspacer` 未读统计范围设置。
- 新短信完成骚扰识别。
- 历史骚扰扫描完成。
- 手动标记短信为骚扰或非骚扰。
- 归档或取消归档会话。
