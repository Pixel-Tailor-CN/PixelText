# Smartspacer 未读数量统计范围设计

## 背景

本需求提出时，`Smartspacer` 未读数量直接按系统短信表中的未读收件箱短信数量统计，不区分普通短信、骚扰短信和归档短信。应用内主列表、骚扰拦截页、归档页的可见范围与 `Smartspacer` 计数口径不一致，容易让用户看到“应用里没有未读，但 Smartspacer 仍显示未读数量”的体验割裂。

## 目标

- 为 `Smartspacer` 未读数量增加可配置统计范围。
- 配置项仅影响 `Smartspacer` 未读数量，不影响点击跳转行为。
- 支持以下 3 个独立开关，默认全部开启：
  - 正常短信
  - 骚扰短信
  - 归档短信
- 统计口径按消息级别并集计算，同一条短信即使同时命中多个分类，最终只计数一次。

## 分类定义

- 正常短信：未读、非骚扰、未归档。
- 骚扰短信：未读、统一最终分类为骚扰；包含显式规则和人工纠正，不只依据原始模型阈值。
- 归档短信：未读、所在会话已归档。

说明：

- “骚扰”和“归档”是可叠加标签。
- “正常短信”是互斥补集，只包含既不骚扰也不归档的未读短信。

## 统计规则

给定一条未读短信：

1. 先判断它是否属于归档会话。
2. 再判断它是否被标记为骚扰短信。
3. 最终计入条件为以下逻辑或：
   - 开启“正常短信”且该短信既不骚扰也不归档。
   - 开启“骚扰短信”且该短信被标记为骚扰。
   - 开启“归档短信”且该短信所在会话已归档。

当 3 个开关全部关闭时，`Smartspacer` 不显示未读数量。

## 数据来源

- 未读短信基础集合：系统 `Telephony.Sms` 收件箱中 `READ = 0` 的短信。
- 骚扰标签：主库 `mirror_message` 的最终骚扰标记，经 `UnreadSmsQuery` 查询。
- 归档标签：`MessageMirrorDatabase` 中的 `archived_conversation` 表。
- 实际计数统一由 `UnreadSmsCounter` 完成；旧独立分数库与归档库只属于迁移来源。

本次只调整现有 `UnreadSmsComplicationProvider` 的短信未读数量逻辑，不扩展到 MMS。

## UI 方案

当前配置入口由 Smartspacer 打开 `UnreadSmsComplicationConfigActivity`，不在应用通用设置页另设统计范围弹窗。页面显示正常、骚扰、归档三个独立开关，编辑临时状态，点击“保存”后写入并通知对应实例刷新；返回不保存。

设置由 `UnreadSmsComplicationSettingsRepository` 按 `smartspacerId` 独立保存。读取顺序为实例配置、默认配置、旧 `app_settings` 值，最终三项均默认开启；保存实例值时同时更新默认配置。全部关闭时页面提示“未读数量已隐藏”。

## 实现边界

- 不改 `Smartspacer` 点击后的跳转行为。
- 不改验证码 `Smartspacer` 目标卡片逻辑。
- 不新增单元测试，验证方式遵循项目约束，使用 Kotlin 编译检查。

## 联动刷新

由于未读数量将依赖骚扰标签和归档状态，以下变化后都需要通知 `Smartspacer` 刷新：

- 修改 `Smartspacer` 未读统计范围设置。
- 新短信完成骚扰识别。
- 历史骚扰扫描完成。
- 手动标记短信为骚扰或非骚扰。
- 归档或取消归档会话。
