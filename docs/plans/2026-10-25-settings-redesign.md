# 设置界面重设计方案

日期：2026-10-25。状态：已实施；Gemini 4 Argon High 已完成实际界面截图审查及修正后复核，代码审查与模拟器验证已完成。

验证：Debug APK 构建、Lint 与差异检查通过；覆盖深浅主题、大字体、宽窄屏、分类导航与返回、自动删除确认、验证码通知联动和资源更新入口。通知关闭状态在当前模拟器未能稳定复现，仍需设备复验；TalkBack 实操和运营商短信、彩信链路不在本轮已验证范围内。

## 目标与依据

将设置从长列表改成「分类首页 → 分类设置 → 必要的专用编辑页」，方便国内 Pixel 用户按目的找到选项。采用 PixelTelo 的连续圆角分组、状态摘要和独立分类页，结合 Android 设置的搜索入口、分类图标和清晰层级。

本次实际查看了 PixelTelo 设置首页、显示与提醒页，PixelText 设置首页，以及模拟器 Android 17（API 37）的系统设置。PixelTelo 源码参考为 `SettingsScreen.kt`、`settings/SettingsCategory.kt`、`settings/SettingsGroup.kt`；PixelText 配置核对 `SettingsScreen.kt`、`AppSettingsRepository.kt` 及现有专用编辑页。截图与调查记录仅留在忽略的工作目录，不作为本文长期依赖。

官方参考：[Android 17 发布说明](https://developer.android.com/blog/posts/android-17-is-here?hl=en)、[Material 3 Expressive 设计介绍](https://blog.google/products-and-platforms/platforms/android/material-3-expressive-android-wearos-launch/)。具体布局依据本机实际截图；下述尺寸为本项目建议值，不声称是 Android 官方强制规格。

主要问题：模型与资源管理占据当前首页首屏；「应用功能」混合了收信、拦截、验证码与显示；大量开关缺少分层；部分依赖项只置灰，原因不容易发现。现有专用图标、手势和会话编辑页面值得保留。

## 推荐方向

采用七分类首页，按使用频率与目的排列为三组。首页只呈现分类、当前状态和导航，不放业务开关。保持原点系列的 Material 3 风格，不新增全局底部导航，不展示巨大的品牌卡片。

| 分组 | 分类 | 首页摘要示例 |
| --- | --- | --- |
| 日常使用 | 消息与验证码 | 智能卡片、验证码管理与彩信 |
| 日常使用 | 骚扰识别与拦截 | 本地识别已开启 · 3 条关键词 |
| 日常使用 | 显示与外观 | 应用图标、会话样式与通知操作 |
| 数据与资源 | 模型与资源 | 离线模型、卡片规则与发件方资料 |
| 数据与资源 | 备份与维护 | 备份恢复、数据同步与修复 |
| 应用信息 | 权限与默认应用 | 已设为默认短信应用 / 需要通知权限 |
| 应用信息 | 关于与帮助 | 当前应用名称 · 实际版本名称（默认 Pixel Text） |

摘要来自真实状态，不固定写“正常”或虚构上次备份日期。避免过长摘要；骚扰模型关闭但关键词仍启用时要同时说明，不笼统显示“拦截已关闭”。

首页顶部采用紧凑标准标题栏：返回与「设置」标题。表中的三个分组名称仅用于设计说明，首页不渲染组标题，以 24dp 留白分隔。仅当默认短信角色或必要权限缺失时，在分类之前出现一条可操作提示；正常状态不额外占一张卡片。权限页仍完整列出状态。优先提高首屏分类可见度，但不强制压缩行高来保证所有字号、窗口都一屏放下。

首批延期设置搜索：先验证七分类与状态摘要是否足以解决查找问题，不放无功能的搜索框。后续若需要搜索，在标题栏右侧提供入口，按需展开；仅本地检索设置标题、说明、旧名称与关键词，不搜索短信正文、不联网。结果应包含分类路径、定位高亮与返回上下文。

## 配置项归属与页面层级

### 显示与外观

保留本轮用户指定的通知图标、时间格式、手势和通知操作归属，不再移到另一个首页分类。二级页内分三个组：

| 分组 | 设置 | 交互 |
| --- | --- | --- |
| 应用与主界面 | 应用名称与图标 | 现有专用页：名称、图标预览及应用按钮；入口展示当前真实桌面图标 |
| 应用与主界面 | 底部未读数量 | 原「未读红点提醒」，开关；明确指底部会话按钮上的数量 |
| 会话列表与详情 | 会话详情显示 | 现有专用页：日间/暗黑、接收/发送文字与气泡、背景图、背景取色、输入区与提示文字、文字缩放、SIM 信息、恢复默认 |
| 会话列表与详情 | 短信时间显示格式 | 两种格式的单选弹窗，附同一条合成短信的时间示例；沿用人性化时间/详细时间的实际语义 |
| 会话列表与详情 | 滑动操作 | 现有左右滑动专用页，保留实际选项和方向语义 |
| 短信通知 | 短信通知图标 | 现有图标选择页，提供状态栏单色预览；实际选项为双气泡、单气泡、信封、文本气泡 |
| 短信通知 | 通知快捷操作 | 现有专用页，保留按钮排序、文案编辑、验证码占位符校验、预览和显式保存；普通短信隐藏复制按钮 |
| 短信通知 | 验证码通知快捷复制 | 开关，解释其控制通知中的复制操作 |
| 短信通知 | 锁屏时隐藏验证码 | 紧随快捷复制，保留当前依赖条件；不可用时写明原因 |

会话详情页保持现有保存机制；应用名称与图标页保持当前草稿/应用机制，统一底部操作样式，但不因视觉重设计悄悄改变返回保存行为。无需新增全局配色、字体或主题设置；沿用应用既有暗色与 Dynamic Color。

### 消息与验证码

三个分组：

- **短信卡片**：智能短信卡片、验证码默认显示原文。说明卡片在会话内的呈现方式；原文项说明“开启智能卡片时，在验证码下方显示完整短信”，不擅自新增禁用条件。
- **验证码清理**：自动删除验证码、验证码保留时间。保留时间常驻显示；未开启自动删除时禁用并说明“开启自动删除后生效”，避免选项突然出现导致页面跳动。继续使用现有合法范围与保存值。
- **彩信**：自动下载彩信，保留可能使用移动数据的说明。单个开关不再拆成只有一项的三级页。

在验证码组末尾放标准导航行「验证码通知与锁屏隐私」，摘要反映实际复制与锁屏设置状态，跳转并定位「显示与外观 → 短信通知」。只保留一处实际开关，返回时回到消息与验证码的原位置。

### 骚扰识别与拦截

不要把「骚扰短信识别」做成控制整页的总开关：它实际只控制本地模型，关键词规则独立运行。

| 分组 | 原配置 → 建议文案 | 行为 |
| --- | --- | --- |
| 识别规则 | 骚扰短信识别 → 本地模型识别 | 开关；说明关闭后关键词规则仍生效 |
| 识别规则 | 关键词拦截 | 现有管理页；摘要显示关键词数量 |
| 识别规则 | 骚扰识别白名单 → 号码白名单 | 现有号码/正则管理页；摘要显示规则数量，并明确命中时优先放行，不受模型或关键词拦截 |
| 处理方式 | 骚扰短信不提醒 | 开关，作用于模型或关键词判定的骚扰短信 |
| 处理方式 | 骚扰短信自动执行 → 收到骚扰短信后 | 不额外处理 / 标为已读 / 删除；仍依赖“不提醒” |
| 内容显示 | 隔离显示骚扰短信 → 单独显示骚扰短信 | 保留当前普通与骚扰会话隔离逻辑 |
| 内容显示 | 骚扰短信默认显示全文 → 默认展开骚扰短信 | 保留当前内容展开逻辑 |

处理动作在单选弹窗中解释后果；选择删除时已有显式确认，确认前不写入删除策略。当前分类还提供「个人学习」和「我的上报」两个同级入口，详见[个人学习界面方案](2026-11-05-personal-learning-ui.md)；本地学习默认关闭，贡献样本必须由用户确认上传，不能写成整款应用完全不联网。

### 模型与资源

- **当前资源**：离线模型、智能卡片规则、发件方名称与头像。把 `builtin` 呈现为「内置版本」，技术版本在详情中查看；未安装发件方资料时显示「未安装」和下载入口。
- **更新设置**：检查资源更新、自动检查资源更新、检查间隔。明确自动检查只获取更新信息，不等于自动下载；通知权限缺失时说明无法接收更新提醒。检查间隔常驻，关闭自动检查时禁用并说明原因。
- 继续使用现有可滚动更新底部面板呈现版本、说明、下载进度、失败重试与安装结果，不新增资源详情三级页。资源详情中保留模型、词表、规则版本及实际更新时间信息。
- 更新通知通过 `EXTRA_TRIGGER_RESOURCE_UPDATE_CHECK` 唤起时直接进入本分类并触发既有检查/面板，不只落在设置首页。
- “删除下载的模型/规则文件”仍受现有调试开关保护，解锁后在关于与帮助底部原地展开，不新增仅有两项操作的三级页。

### 备份与维护

- **备份与恢复**：进入现有完整流程，保持选择内容、加密导出、文件预览、恢复保护、进度与结果。明确不包含彩信、附件及应用名称与图标选择；恢复保护生效时在首页分类摘要及本页展示实际状态。
- **数据维护**：强制同步短信数据（可展示为「重新同步短信」）、重新识别全部短信、刷新 Smartspacer 数据。每项解释实际影响，继续使用现有确认和任务互斥条件。
- 不因页面迁移新增定时清理、云备份、云同步或新的上传行为。

### 权限与默认应用

页首显示默认短信应用状态，提供系统角色申请入口；下方分别呈现电话、短信、联系人和账号、通知权限，沿用现有请求链路。

每项显示当前状态、用途和授予入口，不绘制无法直接修改的假开关。保留应用内解释、默认短信角色申请与运行时权限的串联链路；常规授权显示“去授权”，只有确实打开系统设置页时才使用外部跳转标记。返回应用后刷新状态；被拒绝的权限给出具体说明，保留无需此权限的其余设置可用。

### 关于与帮助

- 顶部小型应用标识、当前品牌名称，合并展示版本名称与版本号，继续保留原版本号点击解锁调试逻辑。
- 开源声明、Pixel Tailor、Telegram 频道保留；站外入口明确标记。
- 早期放在「帮助改进」的样本入口已被「骚扰识别与拦截 → 我的上报」替代，关于分类不再重复提供该入口；贡献仍需人工检查及确认，绝不自动提交。
- 解锁后在当前页底部响应式展开「调试工具」分组，包含删除下载的模型文件、删除下载的智能卡片规则文件，保留原操作能力与保护条件。

## 视觉规范

| 元素 | 建议 |
| --- | --- |
| 页面底色 | 与现有导航转场一致的 `MaterialTheme.colorScheme.background`，暗色保持可辨别层次 |
| 分组底色 | `surfaceContainerLow`；若暗色相邻层过近，评估 `surfaceContainer` |
| 圆角 | 分组外角 24dp、行内接缝 4dp，行间 2dp，参考 PixelTelo |
| 间距 | 页面左右 16dp，组间 24dp，组标题与内容 8dp |
| 行高度 | 有摘要最低 72dp，无摘要最低 56dp；大字体允许自然增高 |
| 字体 | 首页与二级页使用现有标准标题栏字号；行标题 16sp、摘要 14sp，沿用系统字体 |
| 首页图标 | 24dp 图标置于约 40dp 淡色容器内；三种主题色调区分用途，不给每项任意染色 |
| 二级页图标 | 对齐 PixelTelo，采用无圆底的 24dp 单色图标；应用身份入口使用真实桌面图标预览 |
| 尾部控件 | 导航箭头、当前值、开关、外部跳转四种语义明确，不混用 |
| 动效 | 分组和页面切换使用轻量 Material 动效；尊重减少动画设置 |

不引入厚阴影、渐变玻璃效果或嵌套卡片。应用图标预览、会话预览等确有独立对象含义的区域可以使用卡片。

常规设置整行可操作，开关行合并为一个 TalkBack 语义节点，最小触摸目标 48dp；状态不能只靠颜色。最终需验证文本对比度、大字体换行和焦点顺序。宽屏采用左分类、右详情的双栏呈现；窄屏保持完整返回栈，不能硬锁竖屏。

## 页面与弹窗的分工

需要预览、排序、编辑列表或多项联动的功能使用完整页面。只有两个选项的时间格式、有限的更新间隔/处理动作、简单数值输入与破坏性确认保留弹窗。资源更新沿用可滚动底部面板，避免所有单个配置都变成空旷三级页。

一般开关即时保存。应用身份、会话外观与通知快捷操作保留各自现有的显式应用/保存，以及未保存修改的返回处理。分类间切换保持滚动位置；返回键、顶部返回和系统返回手势行为一致。搜索可以直接定位深层项目，但返回时回到原搜索上下文。

## 实施范围与验收建议

建议分两批实施，但最终包含全部七分类：

1. 提取统一分组/设置行组件，完成分类导航和配置迁移，优先打通「首页 → 显示与外观 → 应用名称与图标」；保留全部设置键、默认值和既有后台行为。
2. 完成状态摘要、权限异常提示、资源更新面板和其余专用页的视觉统一；处理宽屏与无障碍适配。本地设置搜索延期，不属于首批必做项。

实施前建立设置项清单，按本文逐项对应，特别核对条件显示的保留时间、更新间隔、调试工具。现有深链需兼容，主题/配置重建不得丢失当前页或重新跳回首页。

验收包括：全部旧配置可找到且值不变；导航/跨分类定位/返回状态正确；灰置项原因明确；模型关闭不误禁关键词；通知复制与锁屏隐藏关系正确；危险操作确认保留并验证新增删除策略确认；浅色/暗色/Dynamic Color、大字体及宽窄窗口可用。按项目约定执行 Kotlin 编译与 Lint，不新增或运行单元测试。模拟器验证导航与布局；默认短信角色、通知操作等系统行为需另外进行设备验证。

七分类与专用页面接线已在 `SettingsScreen.kt` 和 `ui/screen/settings/` 中实现。设计阶段的外部视觉讨论是历史背景，当前维护以源码和项目界面规范为准；本次文档核对没有重新执行设备或无障碍验收。

## 与 Gemini 讨论后的取舍

接受七分类、显示页 2+3+4 分组、资源更新面板和调试项原地展开、跨分类状态导航、首批延期搜索，以及修正权限与备份边界。保留多数现有配置名称，避免为改版而全部改名；采用较短的「模型与资源」，摘要解释具体内容。

初版生成概念图仅用于讨论，不能作为逐像素实现稿：其中通知图标“经典”并非真实选项，二级页彩色圆底、非原生开关、常驻搜索框和首组排序均已在本修订中纠正。桌面图标与通知小图标是两套配置，摘要读取用户当前值，不用图中示例覆盖用户偏好。最终控件与尺寸以本方案及原生 Compose 组件为准。

讨论后生成的第二版概念图已更新分类顺序、配置分组和单色图标。其二级页省略了分组标题，首页遗漏返回按钮，应用身份仍使用占位图标，开关轮廓也未准确还原原生 M3；实施时须按本文补齐，不照抄图中的这些细节。
