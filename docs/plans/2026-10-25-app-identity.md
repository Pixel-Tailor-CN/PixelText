# 应用名称与图标切换

## 已确认设计

默认名称为「Pixel Text」，默认使用经典蓝色图标。首次安装及没有名称、图标配置的旧版升级均使用此组合，已保存的自定义选择继续保留。保留原点尺素、原点短信、原点简讯、尺素、短信作为名称选项；图标提供叠语、原点、小零和经典版本，杏色旧标识仅保留兼容。名称与图标独立选择，预览后统一应用。

设置入口位于「显示与外观」，进入独立页面，沿用通知图标选择页的返回导航和双列图标卡片。顶部展示组合预览，底部固定「应用」按钮，应用后留在当前页面；直接返回放弃尚未应用的修改。应用内主标题随选择更新。Android 通知顶部的应用名由系统提供，固定为 Pixel Text（Debug 构建带 Debug 后缀），不承诺随桌面别名切换；短信通知小图标仍使用原有独立设置。

## 实现步骤

1. Domain 增加名称、图标枚举与组合模型；Data 通过持久化设置和 PackageManager 管理桌面入口。Koin 注册仓库，独立 ViewModel 暴露状态及应用结果。
2. 为全部名称和图标组合声明 activity-alias，默认仅开启 Pixel Text／经典。别名指向无界面的 LauncherActivity，立即转发至 MainActivity 并结束；转发入口使用 relinquishTaskIdentity 将任务身份交给主界面，避免禁用别名时系统关闭当前界面。MainActivity 本体始终可供显式 Intent 启动；默认短信角色必需的接收、发送、回复组件不变。
3. 依据已生成并确认的概念图制作 Android 自适应矢量资源，保留经典资源，提供单色主题图标。
4. 设置页新增预览和选项界面；主界面与 Mock 标题使用当前选择。系统应用名保持 Pixel Text，系统应用图标与启动背景使用经典蓝色资源。
5. 执行 Kotlin 编译、Lint、APK 构建与独立代码评审，检查合并后的 Manifest。

## 切换与恢复

Android 13 及以上使用批量组件状态更新；Android 12 先开启目标入口，再关闭旧别名。只操作本应用预定义的别名，不能禁用 MainActivity。失败时报告错误并恢复可启动入口；启动时及收到本应用覆盖升级广播 MY_PACKAGE_REPLACED 后协调保存的选择与实际组件状态，关闭因默认别名变化而额外启用的入口。持久化保存稳定枚举标识，未知标识回退默认项。

偏好独立保存在 app_identity.xml。系统备份或设备迁移恢复后在启动时协调入口；应用内手动备份仍沿用现有格式，不包含此项，恢复手动备份不会改变当前名称和图标。

## 验收重点

- 首装及无自定义选择的旧版升级默认使用 Pixel Text 和经典蓝色图标；每种组合只保留一个桌面入口。
- 应用、关闭、重新打开和设备重启后选择一致；取消编辑不修改设置。
- 旧版升级后能启动；切换时桌面固定位置、未读角标和启动器缓存需真机确认。
- 默认短信角色、收信、通知点击、回复、分享发送及快捷设置磁贴入口不受影响。
- 暗色、动态取色、主题图标以及大字体下选项可读。
- 不上传短信，不新增权限；不新增或运行单元测试。
