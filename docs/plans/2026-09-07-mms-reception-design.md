# MMS 完整接收方案

状态：用户已审查通过（2026-09-07）；HTML 已确认采用系统 WebView 离线查看。

## 目标与已确认选择

让 PixelText 具备从接收通知、下载、持久化到查看及导出附件的完整 MMS 接收体验。
音视频使用 Media3，图片使用 Coil。后续单独实现用户主动编辑和发送 MMS；本次模型保留复用空间，但不预建发送界面。
协议要求的接收确认属于接收链路，不能因为发送功能后做而遗漏；先核实系统 MMS 服务承担的行为，再补应用实际负责的部分。

本方案对“完整”的定义：

- 已收到并可读取的 part 不因缺少专用卡片而消失。
- 常见图文、动态图、音视频、HTML、名片、日历提供相应查看方式。
- 普通文件和未知格式可查看元数据、保存、分享，并尝试用外部应用打开。
- 原始数据、附件状态与展示结果分离；解码失败不会导致原始附件被删除。
- 不支持的编码、损坏数据和受保护内容给出具体状态及保留附件的操作，不承诺所有历史编码和 DRM 都能原生播放。
- 下载后的解析、分类、缩略图和内容查看均在本地执行。

## 已核实的工程基础

- MirrorMessageModel 已保留所有 part 的 MIME、字符集、顺序、名称、文件名、CID、Content-Location、文本及附件状态。
- MirrorAttachmentStore 已将附件复制到应用私有目录；同步层有复制失败恢复和删除清理机制。
- 当前 MessageModel 适配器仅输出文本和 imageUris，导致其他附件从会话展示模型中消失。
- 当前图片渲染使用 BitmapFactory；工程还没有 Coil 或 Media3 依赖。
- 现有 FileProvider 仅覆盖下载 PDU 目录，不能直接作为镜像附件的对外打开方案。
- 接收器目前只按 M-Notification.ind 处理 WAP Push；完整接收需进一步核实其他接收 PDU 和平台服务的职责。

## 展示架构

Domain 层新增具有明确字段的 MMS 内容模型，包括文本、图片、音频、视频、HTML、联系人、日历、文件、演示页及异常状态。
每项保留对应源 part 标识，附件状态单独表达待下载、准备中、可用、失败和源不可读。
Data 层负责读取内联文本或本地附件流、字符集解码及附件导出；避免在 Compose 中读取文件或解析内容。
ViewModel 暴露已经解析的展示状态，异步解析按消息标识和 revision 失效，旧解析结果不能覆盖新消息状态。
会话页面和独立消息详情共用内容渲染组件；短信智能卡片继续沿用现有工厂。
会话摘要、检索正文、通知摘要使用可读文本和附件类型摘要，不能把 SMIL、vCard 或 HTML 源代码当普通短信正文。

尽量从已有镜像数据派生展示结构。如需要增加嵌套关系或持久化派生字段，提供明确 Room Migration，禁止破坏性重建数据库。
附件仍通过消息、part 与 revision 关联，避免把私有文件路径作为业务身份。

## HTML 方案比较与建议

| 方式 | 收益 | 局限 |
| --- | --- | --- |
| 仅转 Compose 文本 | 列表轻量、统一主题 | 表格、排版和内嵌图片信息损失较多 |
| 应用内离线 WebView | 可显示布局，能够解析本条 MMS 的本地附件引用 | 需要资源映射、导航限制和生命周期管理 |
| 直接交外部浏览器 | 复用浏览器界面 | 私有附件 URI、CID 和相对路径无法保证由外部浏览器正确解析 |

建议使用文字摘要加独立离线 WebView 查看页：

1. 会话内用 Compose 展示可读摘要和“查看完整内容”入口，列表不为每条 HTML 常驻 WebView。
2. 通过 WebViewAssetLoader 的受限资源处理器提供本条消息的 HTML 和附件，按 CID、Content-Location 映射引用。
3. WebView 不执行 JavaScript、不注册原生桥、不提交表单、不允许任意文件读取、不自动加载远程图片或样式。
4. 未命中本消息资源的请求必须明确拒绝，不能回落到网络请求。HTML/XML 解析禁用外部实体解析，并限制输入大小和嵌套。
5. 用户点击 HTTP/HTTPS 链接时沿用现有链接确认体验，交由外部浏览器打开。电话号码与邮件链接通过明确的用户操作调用对应系统界面。
6. 保留原始 HTML 的保存入口；展示副本中的链接重写不修改原始附件。
7. 深色模式、字体缩放和宽表格在查看页处理；不保证任意网页脚本或远程站点功能可运行。

独立查看页的外壳使用 Compose；WebView 通过 AndroidView 嵌入，不新增 XML layout。

## 图片、音频与视频

- Coil 负责本地图片、加载占位、失败展示、采样及缓存，增加动态图解码模块；本功能不需要安装 Coil 网络加载模块。
- 图片支持点击放大、缩放查看和导出；GIF/动态 WebP 支持动画，离屏或页面不可见时停止消耗播放资源。
- Media3 播放本地音视频，音频卡片展示时长、播放/暂停和进度，视频展示缩略图并进入播放器。
- 控件使用 Compose；播放器与页面生命周期绑定，音频焦点、切后台、耳机断开、消息删除和切换播放项都有明确处理。
- 同一时间只播放一个用户选择的媒体，默认不自动播放带声音内容。
- 播放失败展示原因分类并提供打开/保存原文件的操作。格式标记为音视频不等于设备一定能解码。
- 列表不预加载全部媒体，不一次性把大附件读入内存。

## 名片与日历

名片使用独立 Material 3 Compose 卡片：

- 展示头像或姓名首字、姓名、公司、多个电话号码和邮箱；地址、职位、备注等放在展开详情。
- 支持一份文件包含多个联系人；支持常见 vCard 2.1、3.0、4.0 的折行、转义、字符集与编码差异。
- 卡片提供复制、打开拨号界面、邮件界面、添加联系人，以及保存/分享原始名片。
- 添加联系人交给系统确认界面；没有匹配应用时明确提示，并保留导出操作。
- 不认识的字段保留在原始附件中，解析局部失败时仍可打开或保存文件。
- 解析器放在 Domain/Data 边界的专门组件中，UI 不解析 vCard。实现前核实可复用库的许可证、Android 兼容性和体积，再选择成熟解析库或范围明确的本地解析实现。

日历采用事件卡片，展示标题、起止时间、时区和地点，提供系统日历创建入口及原文件导出。
重复规则、多事件等不能被静默截断；无法完整表达时说明并允许交由外部日历应用处理。

## SMIL、multipart 与文本

- MIME 类型统一处理大小写及参数，并保留原始标记。
- 同时处理 Provider 内联文本和附件流中的文本，按声明字符集解码，保留失败状态及原始数据。
- 嵌套 mixed、related、alternative 保留结构与子项；展示 alternative 时选择可用版本，避免重复正文。
- SMIL 支持常见 MMS 的 seq/par、媒体引用、页面分组、顺序及持续时间，提供手动翻页与显式启动的顺序播放。
- 演示页采用适合手机的响应式排版；不承诺复刻所有历史终端的绝对像素布局或任意 SMIL 动画语言。
- SMIL 引用只在本条 MMS 内解析。未被引用的附件仍可在附件列表找到，损坏或无法解析的 SMIL 回退到全部实际内容。
- SMIL 页播放与 Media3 的生命周期及单播放器策略统一协调，避免翻页后声音继续播放。
- 保留解析器现有深度、数量和字节上限，补嵌套处理时不能放大内存风险。

## 接收生命周期

逐项核实并完成：

1. 默认短信角色与正确的 SIM 绑定，通知去重及异常退出恢复。
2. 手动下载、已有自动下载开关、超时、网络失败、过期状态和可重试行为。
3. 下载成功后持久化、地址与主题解码、附件完整复制、会话刷新与通知更新。
4. 多参与方地址保留及会话归集，不在本次加入群发编辑或发送逻辑。
5. M-NotifyResp.ind / M-Acknowledge.ind 等接收协议响应的系统与应用责任边界，避免遗漏或重复响应。
6. 投递/阅读报告等传入 PDU 的分流与合理记录；未能关联本地消息时不能误建普通彩信占位。
7. 下载中删除、重复 Push、重复回调、进程终止、重新启动、附件源失效时的状态一致性。

应用解析和查看过程不直接访问 MMSC；MMSC 网络访问仍仅服务于下载与必要协议交互。

## 测试环境与已发现的限制

2026-09-07 已只读确认：

- D:/AntiGravityProjects/MMSC 存在模拟服务端和测试客户端。
- localhost:8080/api/messages 可访问，当前有 3 条消息记录。
- emulator-5554 与 emulator-5556 均在线，Android 版本均为 16。
- 5554 默认短信应用为 vip.mystery0.pixel.text.debug；5556 为 com.android.messaging。
- 现有存储 PDU 中发现 application/smil 与 audio/3gpp 标记；其他 MIME 可能使用 WSP 整数编码，不能靠字符串扫描断言类型缺失。
- 控制台生成测试消息的代码使用文本 boundary multipart，而 PixelText 解析器处理 WSP 二进制 multipart；测试客户端还把 boundary 参数拼进内容类型字符串。此类样例需先校正和验证，不能直接当作接收兼容性基准。
- MMSC 文档记录了模拟器连接结束时偶发截断的兼容措施，端到端验收需核对接收端数据，不能只看服务端 Retrieved 状态。

保持 5556 的系统 Messaging 作为独立发送端和对照客户端，5554 验证 PixelText；必要时交换接收端角色完成交叉检查。
不重跑会覆盖现有环境的一键配置脚本，不清空用户现有消息。测试数据使用唯一批次标识。

## 验收矩阵

1. 单独文本、单独主题、纯图片、多图片、图片加正文、纯音频、纯视频、混合媒体。
2. PNG/JPEG、GIF/动态 WebP、可播放和不可播放媒体、损坏或空附件。
3. HTML/XHTML、表格、中文、CID 图片、相对资源、远程资源不自动加载、网页链接外部打开。
4. vCard 多版本、多联系人、折行、中文及编码；日历时区、多事件和导入回退。
5. 文件名为空、未知 MIME、PDF/普通文件、名称重复、大小和导出内容一致性。
6. 多页 SMIL、图文对应、混合媒体顺序、未引用附件、缺失引用、嵌套 multipart、alternative 不重复。
7. 手动/自动下载、失败重试、重复通知/回调、下载中删除、进程终止恢复、旧消息重新读取。
8. 实际 WAP Push → 系统下载 → Provider → 镜像 → UI 全链路；与原始附件比较大小和哈希。
9. 播放、图片查看、文件保存及外部打开实际操作；深色主题、字体缩放与返回导航。
10. 接收确认及报告类 PDU 的处理由协议日志与对照客户端验证，不能仅依赖宽松的 Mock 服务端成功响应。

遵循仓库约束，不新增 app/src/test、app/src/androidTest 或测试依赖，不运行单元测试任务。
使用独立的合成 PDU/端到端测试工具、Mock、编译、Lint 和模拟器操作；样例与验证记录放在已忽略的 docs/.local/ 下，不提交 Git。
两台 Android 16 模拟器可验证应用端端到端流程，Android 12 下限、真实运营商及双实体 SIM 仍需真机补充，报告中分别记录通过、失败和未验证。

## 工作量与交付

按当前扩大后的接收生命周期、离线 HTML 和名片卡片范围，常规工程估算约 15～25 人日；不是自动化执行耗时承诺。
主要不确定项是接收协议责任边界、SMIL 时序、历史名片编码和测试 PDU 质量。
作为一个功能版本交付，内部依次完成：完整模型与解析、附件操作、媒体、HTML/名片/日历、SMIL、接收生命周期、端到端回归。
每个阶段编译与静态检查，最后执行完整接收验收矩阵；没有证据的条目保持未验证。
