# 短信骚扰状态落库

用户已确认：短信保存最终正常／骚扰／未识别状态，模型更新由后台扫描更新，列表直接通过 SQL 过滤，不在读取时重新组合判断。

## 数据与更新边界

- `mirror_message` 保存 `isSpam`（NULL／0／1）、固定整数来源、独立模型评分与模型版本，以及规则、人工覆盖的必要字段。
- 既有优先级保持：白名单／已放行 > 关键词 > 人工纠正 > 模型。保留底层评分，移除覆盖后能够恢复判定。
- 模型变化保留当前判定并安排后台重扫；新结果逐条替换。读取列表不验证模型版本，不计算正文指纹。
- 关键词及白名单仍是独立规则集合。学习样本及训练参数仍服务训练，人工标签变更同步更新所有关联短信。
- 普通已读、会话等元数据更新保留判定；正文或消息身份改变才重置并重新识别。
- 旧三张逐消息判定表仅用于一次性迁移，由 `MirrorSpamLegacyImporter` 导入主库并保存完成标记；主库辅助数据与逐消息判定均确认导入后，再由该导入器清理旧骚扰库文件。`MirrorAuxiliaryDatabaseMigration` 只清理已导入的验证码与归档旧库。`SpamDatabase.kt` 现仅保留关键词实体和 DAO，不再声明独立 Room 数据库；迁移失败可重试。

## 实施与验收

1. 增加镜像字段、索引、原子更新 DAO、旧数据导入，检查普通同步不清除状态。
2. 模型、关键词、白名单、人工纠正写入口改为更新镜像状态；接入新收信和后台重扫。
3. 主列表、骚扰列表直接过滤 isSpam；删除候选正文读取、逐条指纹计算和跨库判定。
4. 编译、Lint；用模拟器验证旧数据迁移、页面加载、规则及人工纠正立即生效、刷新重开状态保持。按项目约定不新增或运行单元测试。
5. 检查差异并记录其他表用途与可精简项；本次不无关改造彩信发送、验证码、归档。

## 重点检查

- 模型旧任务与人工操作并发时不能覆盖人工决定。
- 共享学习样本标签变化更新全部关联消息。
- 迁移只执行一次，异常退出可恢复，不因开页产生重算或写入循环。
- 未识别消息在主列表可见；隔离开关与原有分组、分页语义保持。
- 新短信先同步再写判定，避免 UPDATE 未命中导致结果丢失。
