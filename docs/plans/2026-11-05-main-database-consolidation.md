# 主库合并与关联查询

将骚扰规则、验证码索引与归档状态迁入 `message_mirror.db`，主库版本升级至 7。保留各自 DAO 和业务职责，取消三个独立 Room 数据库。个人学习、发送队列和号码资料库保持现状。

## 存储与升级

- 主库增加关键词、白名单、验证码索引、验证码代次、短信扫描状态及归档状态六张表。
- 归档只保存会话 ID 与归档时间，正文、未读数和排序时间读取短信表。
- 打开主库时事务导入旧库，完成标记与目标数据同时提交；确认提交后清理旧文件。旧骚扰库需等逐短信判定也导入完成才清理。
- 兼容跳过中间版本升级和镜像库首次创建。保留旧备份协议的三个传输文件，运行数据库合并不改变备份格式。

## 查询与写入

- 主列表通过 SQL 排除归档；归档列表关联当前消息，分组取最新消息后排序分页，不再先获取归档 ID 页。
- 验证码列表和正文关联短信主表、正文表，失效的关联不显示；扫描仍从系统 Provider 校验，避免镜像尚未同步时误删结果。
- 规则与最终骚扰标记写入同一主库事务；保留旧版本未完成操作的恢复入口。
- SQL 负责关联、过滤、分组和分页；模型推理、正则匹配、联系人资料解析仍由相应业务层完成。

## 验收

- 合成 SQL 数据覆盖归档过滤、最新时间分页、骚扰隔离、空值和同时间消息，检查执行计划。
- 编译、Debug APK 与 Lint；不新增或运行单元测试。
- 模拟器升级前备份，核对迁移前后数量、主库版本与旧库清理；检查主列表、骚扰、归档、验证码页面及日志。
- 备份导出维持旧 schema；实际短信发送、运营商链路与完整跨机恢复不以构建结果替代实测。
